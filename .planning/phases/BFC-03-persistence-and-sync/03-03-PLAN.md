## Phase Goal

**As a** person who sets up BeFocus to look the way I like, **I want** my look to still be there
the next time I open the app, on this device or another one I sign in on, **so that** I never redo
it and never see the default flash before my look appears.

(Derived from the ROADMAP Phase 3 goal.)

<objective>
Serve the look. `GET /user/settings` returns the active look alongside the settings it already
returns. The new `PUT /user/themes/active` saves it, creating the settings row and the first theme
when needed, and is safe under concurrent saves.

Purpose: SYN-01 and SYN-02. The server is the account's only source, read on the request the
dashboard already makes. SYN-05: the server keeps the last write and never forks a second theme.
Output: the themes route trio, the extended GET, and a signed-in curl transcript in the SUMMARY.
</objective>

**Route** (`routes/themes/themes.route.ts`): `putActiveTheme = createRoute({ path:
'/user/themes/active', method: 'put', tags: ['Themes'], ... })`.

- Request body: `jsonContentRequired(z.object({ look: lookSchema }), 'The active look')`. Use the
  existing body helper from the user routes, whichever it is.
- `lookSchema` comes by relative path from `packages/types/look.ts`.
- Responses:
  - 200 `z.object({ look: lookSchema, themeId: z.string().uuid(), updatedAt: z.string() })`
  - 500 `z.object({ message: z.string() })`
- Export `type PutActiveTheme`.

**Handler** (`themes.handler.ts`) follows RESEARCH Pattern 2 exactly:

1. Take `user = c.get('user')`; if it is missing, return 401, matching the user handlers.
2. Read `const { look } = c.req.valid('json')`. Never spread the body.
3. `db.insert(sessionSettings).values({ id: nanoid(), userId: user.id, workDuration: 1500,
   breakDuration: 300, numberOfSessions: 6 }).onConflictDoNothing({ target:
   sessionSettings.userId })`.
   - These defaults must equal the timer store defaults. Read them from `useTimerStore` /
     `lib/session` and keep them in one place if 07.1 exported constants.
4. Select `activeThemeId` for the user.
5. If it is set, run `db.update(themes).set({ look, updatedAt: new Date() }).where(and(eq(themes.id,
   activeThemeId), eq(themes.userId, user.id))).returning()`. One row means respond 200.
6. If it is unset, or step 5 updated 0 rows:
   - `const id = crypto.randomUUID()`.
   - Run `db.batch([db.insert(themes).values({ id, userId: user.id, look }).returning(),
     db.update(sessionSettings).set({ activeThemeId: id }).where(and(eq(sessionSettings.userId,
     user.id), isNull(sessionSettings.activeThemeId))).returning()])`.
   - If the second result has one row, respond 200 with the inserted theme.
   - If it has 0 rows (a concurrent request set the pointer first), delete the theme with
     `and(eq(themes.id, id), eq(themes.userId, user.id))` and go back to step 4 once. If that pass
     also fails, return 500 `{ message: "Couldn't save the look" }`.
7. Respond with `{ look: row.look, themeId: row.id, updatedAt: row.updatedAt.toISOString() }`.
8. If `db.batch` is not on the neon-http driver type (RESEARCH A5), run the two statements in
   sequence with the same 0-row check and note it in the SUMMARY. The delete-and-retry keeps it
   correct either way.

**Index** (`themes.index.ts`): `createRouter().openapi(routes.putActiveTheme,
handlers.putActiveTheme)`. Add `themes` to the `routes` array in `app.ts`.

**GET look** (`user.route.ts`, `user.handler.ts`) follows RESEARCH Pattern 3:

- The 200 response becomes `getUserSettingsSchema.extend({ look: lookSchema.nullable() })`.
- The handler selects `{ settings: sessionSettings, look: themes.look }` with
  `.leftJoin(themes, and(eq(themes.id, sessionSettings.activeThemeId), eq(themes.userId,
  user.id)))` and `.where(eq(sessionSettings.userId, user.id))`.
- Keep the 404 when there is no row.
- Respond with `{ ...row.settings, look: parsed.success ? parsed.data : null }`, where `parsed =
  lookSchema.safeParse(row.look)` when `row.look` is not null.
- In `tables/settings.ts`, export `type SettingsWithLook = Settings & { look: Look | null }` (type
  import from the relative look path) for the Next server fetch in 03-04.

**createUserSettings** (`user.handler.ts`): the unique index makes "select, then insert" race into
a 500. Change it to insert `.onConflictDoNothing({ target: sessionSettings.userId })` and then
select the user's row. Keep the response shape and status.

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-03 | Elevation of privilege | themes handler | mitigate | Body is `{ look }` only; every select, update and delete filters on `user.id`; the GET join also requires `themes.user_id = user.id`; checked by round trip rows b-d |
| T-03-04 | Tampering | look body | mitigate | Strict `lookSchema` (bounded fields, hex colours, enums) through the zod hook, 422 on failure; row e |
| T-03-09 | Tampering | stale stored look | mitigate | `safeParse` on read, `null` when it no longer parses, so the client falls back to the default look |
| T-03-10 | Denial of service | concurrent first saves | mitigate | `onConflictDoNothing` on the unique user id, a guarded pointer update, and orphan delete with one retry; rows g and h |
| T-03-11 | Spoofing | no session | mitigate | `requireAuth` on `*` unchanged; row f |
| T-03-06b | Information disclosure | throwaway test accounts | accept | Throwaway emails only; cookie jar in the session scratchpad, never the repo |
