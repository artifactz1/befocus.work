## Phase Goal

**As a** person who sets up BeFocus to look the way I like, **I want** my look to still be there
the next time I open the app, on this device or another one I sign in on, **so that** I never redo
it and never see the default flash before my look appears.

(Derived from the ROADMAP Phase 3 goal.)

<objective>
Wire the client. The customize store gains a mode and one save path. Done, close, Escape and route
leave save the look through it. Each layout paints the saved look before first paint, and each mode
hydrates the store from exactly one owner.

Purpose: ENG-05 (no default flash), SYN-01 and SYN-03 (signed-in and guest restore), SYN-05 (rapid
Apply converges on the last look).
Output: the store changes, `LookPaintScript`, both layouts, and the "## Seam map" in the SUMMARY
that Phase 9 plans 09-04 and 09-08 check.
</objective>

**Provider signature:** `CustomizeStoreProvider({ mode, initialLook, children })` with `mode:
'account' | 'guest'`. `createCustomizeStore(mode, initialLook)` keeps the safeParse plus
`DEFAULT_LOOK` fallback, and seeds `active`, `preview` and `persisted` from the parsed value.

**State and actions:**

- Add `mode` to state.
- Add `saveLook(look: Look): void`. It is the only write path. Nothing else in the app calls the
  saver, `writeGuestLook` or the themes route.
  - Account mode: one `createLookSaver` per store with:
    - `send: async (look) => { const res = await api.user.themes.active.$put({ json: { look } }, {
      init: { keepalive: true } }); if (!res.ok) throw new Error(String(res.status)) }`
    - `onSaved: (look) => set({ persisted: look })`
    - `onError: reportSaveFailed`
  - Guest mode: `writeGuestLook(look)`. On true, `set({ persisted: look })`; on false, call
    `reportStorageBlocked()`.
  - Export `reportSaveFailed` and `reportStorageBlocked` from this module as `console.error` stubs
    with a `// 03-05 wires the toasts` comment. 03-05 replaces their bodies only.
- `apply`: `const { preview, active } = get(); if (!lookEquals(preview, active)) get().saveLook(preview);
  set({ active: preview, panelOpen: false })`.
  - Compare with `active`, not `persisted` (CONTEXT save semantics, case f in persistence.check.ts).
  - A failed save is retried on the next change.
- `revert` and `openPanel` stay unchanged.

**Hydration owner (guest):** in the provider's existing painter `useEffect`, before the first
`paint()`:

```ts
if (mode === 'guest') {
  const stored = readGuestLook()
  if (stored) store.setState({ active: stored, preview: stored, persisted: stored })
}
```

This is the only guest read in the app. Account mode never reads browser storage; its owner is the
`initialLook` prop.

**Unmount apply:** add a second effect whose cleanup runs `if (store.getState().panelOpen)
store.getState().apply()`. This covers route leaves out of the layout (for example /guest to
/sign-in) where the panel unmounts without seeing a pathname change. Keep it separate from the
painter cleanup so the order is apply first, then token removal.

Closing the tab with the panel open does not save. That is out of scope (captain pick P2: Done,
close, Escape and route leave).

| browser storage -> paint script / store | Any script on the origin or the user can edit storage |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-03-02 | Tampering / XSS | LookPaintScript | mitigate | Only `buildPaintScript` builds the text (escapes `<`, U+2028, U+2029; value regex; enum attrs); one `dangerouslySetInnerHTML` in the app for it; the `/guest` HTML check proves no account data leaks into the guest page |
| T-03-01 | Tampering | guest storage read | mitigate | `readGuestLook` re-validates with `lookSchema`, so a bad record reads as null and the page keeps the default |
| T-03-12 | Information disclosure | shared device | accept | Guest cache is per browser by design (CONTEXT); the signed-in dashboard never reads it (tokens always passed) |
| T-03-13 | Repudiation / data loss | unmount without Done | mitigate | Unmount effect applies an open panel, so a route leave saves; tab close is out of scope per captain pick P2 |
