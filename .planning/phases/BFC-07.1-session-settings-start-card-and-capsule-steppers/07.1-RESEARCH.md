## User Constraints (from CONTEXT.md)

### Locked Decisions

#### Captain pick (2026-10-16)
- Stepper direction: **D · Capsules**. Each value is a full-width pill: round minus on the left,
  value and unit in the middle, round plus on the right; the name and range sit above the pill on
  one line, with the limit message in place of the range when a limit is hit. The pressed button
  fills with the foreground colour.
- Placement: **P5 · Center card, before you start**, with the "Ask before each session" switch.
- Limits: **proposed**. Focus 5-90 min, Break 5-30 min, both step 5; Rounds 1-12 step 1.

#### Review rounds
- Round 1 (captain): the popover "feels off"; wanted it on a side like Sounds and Customize. Board
  answered with P1 (right panel, own page in the Customize shell); superseded by round 2.
- Round 2 (captain): settings in the middle, popping up when the user is about to start. Agreed
  with one guard rail: only on a fresh start, never on resume or round skips, plus an opt-out.

#### When the start card opens
- "Fresh" means: not running, `isWorking`, `currentSession === 1`, `timeLeft === workDuration`.
  "Finished" means the last round has run out (`currentSession === sessions`, `timeLeft === 0`).
- On fresh or finished, Play (button) and Space (`useTimerKeyboard`) open the start card instead
  of starting, unless the switch is off. Both entry points must call one shared "request start"
  function so the rule lives in one place.
- Resume from pause, skip to next/previous, and R (reset current block) never open it. Reset on
  round 1 makes the session fresh again, so the next Play opens it.
- Start applies the card values, resets to a fresh round 1 (needed when finished or values
  changed), then starts. Enter triggers Start; Esc and Cancel close and leave the timer untouched.

#### Card content
- Start mode: title "Start a session", sub line "Ends around <local time> · Enter to start"
  (start time + rounds x (focus + break) - break), the three capsule steppers under a "Session"
  section header with the live total, the existing `AlarmPicker` as the next section, and a foot
  with the switch on the left, Cancel (ghost) and Start (primary, play icon) on the right.
- Edit mode (footer button): title "Session settings", sub line "Saving restarts the timer",
  same body, foot Cancel and Save. Save keeps today's confirm dialog while a session is in
  progress (not fresh). On a fresh session Save needs no confirm.
- Changes in the card are local until Start or Save; Cancel discards them.

#### Persistence
- Signed-in: Start and Save both persist durations and rounds through `useSaveUserSettings`
  (PUT then POST fallback). Durations stay stored in seconds.
- The switch is a new boolean column on `sessionSettings` (for example `ask_before_start`,
  not null, default true) with a Drizzle migration, added to the settings route schemas (reuse
  the drizzle-zod schemas in `tables/settings.ts`), and delivered through the existing
  server-fetched-then-hydrate path: `getUserSettings()` in `app/(app)/layout.tsx` ->
  `TimerStoreProvider initialSettings` -> the timer store. No client fetch on mount, no flash.
- Guests (`app/guest/layout.tsx`, `initialSettings={null}`): values apply to the store only, as
  today; the switch is kept in that browser (localStorage, wrapped in try/catch) and defaults on.

#### Shell and layout
- One centered card, 400px wide on desktop, `calc(100vw - 32px)` on phones, max height
  `100dvh - 32px` with the body scrolling. Same surface as the Customize inspector and Records
  room (panel surface, hairline border, radius 18, deep shadow), over a dimmed backdrop.
- Built on the existing Radix dialog primitive in `@repo/ui` so focus trap, Esc, aria-modal and
  scroll lock come for free; do not hand-roll a modal.
- Only one surface open at a time: opening the card closes Customize and the Records room, as
  they already close each other.
- The old `SessionSettings.tsx` popover, `SessionSettingsMobile.tsx` drawer and the three
  `components/input/*Input.tsx` files (plus `Counter.tsx` if unused) are removed.

#### Stepper behaviour
- One `Stepper` component used three times. `role="spinbutton"` with `aria-valuenow`,
  `aria-valuemin`, `aria-valuemax`, `aria-valuetext` ("25 minutes"), labelled by its name.
- Arrow Up/Right +step, Down/Left -step, Page Up/Down +/-3 steps, Home min, End max.
- Pointer hold repeats after 400ms at 120ms intervals and stops at the limit.
- At a limit the button is `disabled` and the range line becomes the reason ("Minimum 5 min").
- Targets at least 44px on phones.

#### Technical constraints
- Biome style (single quotes, no semicolons, 100 col). No new dependencies.
- No test runner in the repo; verification is by running the app (`bun run web`, `bun run api`)
  and exercising the flows in a browser, plus `bun run check` and `bun run turbo:build`. A small
  pure helper (for example the fresh/finished rule and ends-around maths) may get a `bun run`
  one-off check script if the plan wants one.
- Keyboard guard in `useTimerKeyboard.ts` already ignores keys inside dialogs; the card is a
  dialog, so Space inside it does not toggle the timer.

#### Specific Ideas
- Sub line on the start card uses the local time format of the browser ("6:08 PM").
- Focus lands on Start in start mode and on the Focus stepper in edit mode.
- Section header "Session" carries the live total ("2h 55m").

<research_summary>
## Summary

Everything needed already exists in the repo; the phase is composition plus one column. The house modal precedent is `components/records/AddSoundDialog.tsx`, which imports `@radix-ui/react-dialog` directly (`DialogPrimitive.Root/Portal/Overlay/Content`) with a CSS module surface, because `@repo/ui`'s `DialogContent` always renders its own X button and shadcn sizing classes. Use the same approach. The timer store (`apps/next/src/store/useTimerStore.tsx`) is a per-layout context store; add `askBeforeStart`, `card`, and four actions there so Play, Space, the command menu and the footer button all route through one `requestStart`.

The most important finding is a timer quirk: when a block reaches 0, `Timer.tsx:75-81` stops the worker but nothing sets `isRunning` back to false, so the "finished" state is `isRunning === true, timeLeft === 0, currentSession === sessions`. The finished predicate must ignore `isRunning`, and `requestStart` must check finished before falling back to `toggleTimer`. The second important finding is layering: `@repo/ui` Select content and AlertDialog both use `z-50`; if the card copies AddSoundDialog's `z-index: 60/61`, the AlarmPicker dropdown and the Save confirm render behind the card. Keep the card at `z-index: 50` so later portals stack above it.

Persistence is cheap: adding `askBeforeStart: boolean('ask_before_start').notNull().default(true)` to `tables/settings.ts` flows through `Settings` (InferSelectModel) into `getUserSettings()` and `TimerStoreProvider`, and through `getUserSettingsSchema` / `updateUserSettingsSchema` into the typed `hono/client` with no route rewiring. The handlers must be edited because they hand-pick fields, and the hand-written client types in `hooks/useSession.ts:6-18` must gain the field.

**Primary recommendation:** Add `requestStart` + `card` to the timer store, build `SessionCard` on `DialogPrimitive` at z-index 50 with Radix default focus return, and add the column via `drizzle-kit generate --name ask_before_start` (migration 0010).
</research_summary>

### Pattern 1: Store additions (one rule, one place)
**What:** extend `TimerState` with `askBeforeStart: boolean`, `card: 'start' | 'edit' | null`, `requestStart()`, `openCard(mode)`, `closeCard()`, `applySettings(values, opts)`, `setAskBeforeStart(v)`. Extend `createTimerStore`'s `initial` with `askBeforeStart` and `TimerStoreProvider`'s `initialSettings` Pick with `'askBeforeStart'` (`useTimerStore.tsx:29-31, 145-162`).
**When:** every start entry point.
**Example:**
```typescript
// apps/next/src/store/useTimerStore.tsx (sketch)
requestStart: () => {
  const s = get()
  const finished = isFinished(s)
  if (s.askBeforeStart && (isFresh(s) || finished)) return set({ card: 'start' })
  if (finished) return set({ ...freshRound(s.workDuration), isRunning: true })
  set({ isRunning: !s.isRunning })
},
applySettings: ({ workDuration, breakDuration, sessions, askBeforeStart }, { start }) =>
  set({
    workDuration, breakDuration, sessions, askBeforeStart,
    currentSession: 1, isWorking: true, timeLeft: workDuration, isAlarmOn: false,
    isRunning: start, card: null,
  }),
```
`isFresh` and `isFinished` live in `lib/session/session.ts` (pure, testable), the store imports them.

### Pattern 2: Close the other surfaces in the opening handler
**What:** `components/session/useSessionCard.ts` mirrors `components/customize/useCustomizeActions.ts:17-20`:
```typescript
export function useSessionCard() {
  const store = useTimerStoreApi()
  const closeCustomize = useCustomizeStore(s => s.apply)
  const closeOthers = () => {
    useSoundsStore.getState().setRoomOpen(false)
    closeCustomize()
  }
  const requestStart = () => {
    store.getState().requestStart()
    if (store.getState().card) closeOthers()
  }
  const openEdit = () => {
    closeOthers()
    store.getState().openCard('edit')
  }
  return { requestStart, openEdit }
}
```
`useTimerKeyboard` (called inside `Timer.tsx:53`, under both providers) replaces `store.getState().toggleTimer()` at line 28 with `requestStart()`; keep its effect deps stable (use a ref or the store api, not a fresh closure each render). `TimerButtons.tsx:35` `onClick={toggleTimer}` becomes `onClick={requestStart}`. `CommandDialogContent.tsx:151` `handleCommand(toggleTimer)` becomes `handleCommand(requestStart)` (discretionary but recommended, so the rule really lives in one place).

Why not close Customize from a `SessionCard` effect: a second commit lets `CustomizePanel`'s focus-return effect (`CustomizePanel.tsx:29-42`, synchronous `el.focus()`) race the card's auto-focus. Closing in the same handler keeps it one commit, and Radix mounts portal content one commit later, so the card's focus wins. [VERIFIED: codebase; ASSUMED: Radix Portal mounts content after a layout-effect re-render]

### Pattern 4: Enter to start
```typescript
const onEnter = (e: React.KeyboardEvent) => {
  if (e.key !== 'Enter') return
  if (e.repeat) return e.preventDefault()          // holding Enter must not re-fire Start
  if (e.defaultPrevented) return
  const t = e.target as HTMLElement
  if (!e.currentTarget.contains(t)) return         // Select content is portaled; React bubbles it here
  if (t.closest("button, a[href], [role='combobox'], [role='switch']")) return // native activation
  e.preventDefault()
  submit()                                         // Start in start mode, Save in edit mode
}
```
Spinbuttons, the slider and empty card space fall through to `submit()`.

### Pattern 5: Stepper (APG spinbutton + press-and-hold)
- Container: name (`id`) and range/hint line above, pill below.
- Value element: `role='spinbutton' tabIndex={0} aria-labelledby={nameId} aria-valuenow aria-valuemin aria-valuemax aria-valuetext='25 minutes'`.
- Keys on the spinbutton: ArrowUp/ArrowRight `+step`, ArrowDown/ArrowLeft `-step`, PageUp/PageDown `+/-3*step`, Home min, End max, each with `preventDefault()`. [CITED: w3.org/WAI/ARIA/apg/patterns/spinbutton] (Left/Right are a CONTEXT addition, not APG.)
- Buttons: `type='button' tabIndex={-1} aria-label='Decrease focus'`, `disabled` at the limit.
- Hold: `onPointerDown` -> `e.preventDefault()` (keeps focus on the spinbutton, so disabling the button never drops focus to body), step once, `setTimeout(400)` then `setInterval(120)`; each tick reads the latest value via a ref and stops when clamped value stops changing. Stop on `pointerup`/`pointercancel` registered on `window` (a button that becomes `disabled` mid-hold stops receiving pointer events), on `pointerleave`, and on unmount.
- `onClick` steps only when `e.detail === 0` (keyboard or assistive-tech activation), otherwise the pointerdown step would double.
- Limit hint replaces the range: "Minimum 5 min", "Maximum 90 min", "Minimum 1 round", "Maximum 12 rounds"; range text "5-90 min", "1-12 rounds" (board `hintText` / `rangeText`, `board.html:506-507`).

### Pattern 6: Switch
Native `<button type='button' role='switch' aria-checked={ask} onClick={() => setAsk(!ask)}>` with the visible text "Ask before each session" inside the button (accessible name). Styling from board `.tgl` (`board.html:330-334`): 30x18 track, 14px knob.

### Anti-Patterns to Avoid
- **Reading `localStorage` during render or in the store initializer for guests:** the guest layout is a client component but is still server-rendered; read in a post-mount effect.
- **Hard-coding `z-index: 60/61` from add-sound.module.css:** hides Select and AlertDialog (Pitfall 2).
- **Calling `useSaveUserSettings().mutate` on every Start:** toasts "Session Settings saved successfully" every session; only save when the draft differs from the store values (Pitfall 7).
- **Spreading the request body into `.set()` / `.values()`:** mass assignment of `userId`/`id`; keep explicit keys.
</architecture_patterns>

<common_pitfalls>
## Common Pitfalls

### Pitfall 1: "Finished" has `isRunning === true`
**What goes wrong:** a predicate that requires `!isRunning` never matches finished, and `toggleTimer` at finished sets `isRunning` false, so Play appears dead.
**Why:** `Timer.tsx:75-81` stops the worker when `timeLeft` hits 0 without changing `isRunning`; the `timeLeft === 0` branch of `decrementTime` (`useTimerStore.tsx:97-117`) only runs if one more tick sneaks in. [VERIFIED: codebase]
**How to avoid:** `isFinished = s => s.currentSession === s.sessions && s.timeLeft === 0` (ignore `isRunning`, `isWorking`); `requestStart` tests finished before toggling; with the switch off, finished resets to round 1 and starts.
**Warning signs:** at 00:00 on the last round the Play button shows the Pause icon (existing, `TimerButtons.tsx:37-44`). Out of scope to change, but expect it during UAT.

### Pitfall 2: z-index hides the Select dropdown and the Save confirm
**What goes wrong:** AlarmPicker's `SelectContent` (`packages/ui/.../select.tsx:70`, `z-50`) and `AlertDialog` overlay/content (`alert-dialog.tsx:20,38`, `z-50`) render under a card at `z-index: 60/61` (the add-sound values, `add-sound.module.css:6,19`).
**How to avoid:** card scrim and card at `z-index: 50`. Later portals append after the card in `body`, so they win at equal z. [VERIFIED: codebase; CSS stacking order is standard]
**Warning signs:** clicking the alarm select "does nothing"; Save in edit mode looks frozen.

### Pitfall 3: Tooltip swallows Escape / pops over the card
**What:** Radix tooltip DismissableLayer keeps a capture Escape listener after the trigger click (`CustomizeButton.tsx:15-18`).
**How to avoid:** footer button and the Play button tooltip use `open={card ? false : undefined}`.

### Pitfall 4: Space opens the card, then the keyup clicks Start
**What:** Space keydown on body opens the card and focuses Start; in some browsers the Space keyup on a newly focused button fires `click`, starting immediately. [ASSUMED: known Firefox behaviour, verify manually]
**How to avoid:** on Start, arm on `onKeyDown` (`' '`) and in `onKeyUp` call `e.preventDefault()` when not armed. Verify in Firefox and Safari.

### Pitfall 5: Enter from inside the AlarmPicker Select
**What:** React synthetic events bubble through portals, so Enter on a Select item reaches the card's `onKeyDown`.
**How to avoid:** `e.currentTarget.contains(e.target)` check (Pattern 4) plus skipping `[role='combobox']`.

### Pitfall 6: Legacy values outside limits
**What:** stored `workDuration` of e.g. 120 min or 23 min would render `aria-valuenow` outside min/max and break the step grid.
**How to avoid:** on open, `clampStep(minutes, limit)` = clamp then round to the nearest step. Cancel changes nothing; Start/Save persist the clamped value. [ASSUMED: acceptable to the user]

### Pitfall 7: Toast and request on every Start
**What:** `useSaveUserSettings` always toasts on success (`useSession.ts:116-119`) and invalidates the query.
**How to avoid:** skip the save when draft equals the current store values and ask flag; for Start, pass a quiet option (e.g. `useSaveUserSettings({ quiet: true })` skipping the success toast; keep the error toast). Save in edit mode keeps the toast.

### Pitfall 8: PUT with no settable keys throws
**What:** `mapUpdateSet` in drizzle-orm filters `undefined` values and throws `"No values to set"` if none remain [VERIFIED: node_modules/drizzle-orm/utils.js:81-93]. `updateUserSettingsSchema` (createUpdateSchema) makes every field optional.
**How to avoid:** in `updateUserSettings`, build the set from `c.req.valid('json')` with explicit keys (undefined keys are skipped, so command-menu saves without `askBeforeStart` leave it unchanged) and return 400 if the object is empty.

### Pitfall 9: Hand-written client types drift
**What:** `hooks/useSession.ts:6-18` types `UserSettings` and `UserSettingsInput` by hand; `askBeforeStart` will be missing even though the hono client returns it.
**How to avoid:** add `askBeforeStart: boolean` to `UserSettings` and `askBeforeStart?: boolean` to `UserSettingsInput`.

### Pitfall 10: Command menu opens the card while its own dialog closes
**What:** `useCommandHandler` runs `action()` then `setOpen(false)` (`useCommandMenuHooks.tsx:257-264`), so two Radix dialogs overlap for one commit; the command dialog's focus return may run after the card's auto-focus.
**How to avoid:** acceptable because the card's FocusScope traps and refocuses; verify in UAT. If focus lands outside, swap order for this command (close first, then `requestAnimationFrame(requestStart)`).

### Pitfall 11: CLAUDE.md is stale on hydration
`hydrateFromSettings` / `DashboardShell` do not exist. Plans must name `TimerStoreProvider initialSettings` instead. [VERIFIED: grep]

### Pitfall 12: The only path to turn the start card back on
The board and CONTEXT put the switch only in the start-mode foot. Once off, the start card never opens, and edit mode has no switch, so the user cannot turn it back on. See Open Question 1.
</common_pitfalls>

// apps/next/src/lib/session/session.ts
export const LIMITS = {
  focus: { min: 5, max: 90, step: 5 },
  break: { min: 5, max: 30, step: 5 },
  rounds: { min: 1, max: 12, step: 1 },
} as const
export const ASK_KEY = 'befocus.askBeforeStart'
type T = { isRunning: boolean; isWorking: boolean; currentSession: number; sessions: number; timeLeft: number; workDuration: number }
export const isFresh = (s: T) => !s.isRunning && s.isWorking && s.currentSession === 1 && s.timeLeft === s.workDuration
export const isFinished = (s: T) => s.currentSession === s.sessions && s.timeLeft === 0
export const clampStep = (v: number, { min, max, step }: { min: number; max: number; step: number }) =>
  Math.min(max, Math.max(min, Math.round((v - min) / step) * step + min))
export const totalMinutes = (f: number, b: number, r: number) => r * f + (r - 1) * b
export const formatTotal = (m: number) => `${m >= 60 ? `${Math.floor(m / 60)}h ` : ''}${m % 60}m`
export function readAskBeforeStart(storage: Pick<Storage, 'getItem'> | undefined = globalThis.localStorage) {
  try { return storage?.getItem(ASK_KEY) !== '0' } catch { return true }
}
export function writeAskBeforeStart(v: boolean, storage: Pick<Storage, 'setItem'> | undefined = globalThis.localStorage) {
  try { storage?.setItem(ASK_KEY, v ? '1' : '0') } catch {}
}
