# Phase 7.1: Session Settings Start Card and Capsule Steppers - Context

**Gathered:** 2026-10-16
**Status:** Ready for planning
**Source:** Captain pick on the session settings design board (Lavish session
http://127.0.0.1:4387/session/97294d883249ee12, file `.lavish/settings/board.html` in this worktree,
not committed) plus the ROADMAP.md Phase 07.1 entry. The discuss step is covered by the pick and
the two review rounds below.

<domain>
## Phase Boundary

Replace the Session settings footer popover (desktop) and vaul drawer (phone) with one centered
card, and replace the three duplicated number inputs with one modern capsule stepper. The card
opens on its own when the user presses Play on a fresh session, and from the footer button at any
time. Requirements SES-01..SES-06.

Out of scope: any other settings redesign (Customize, Records room, account), Phase 8 added time
and block records, Phase 9 tasks and time blocks, changes to the alarm controls themselves.
</domain>

<decisions>
## Implementation Decisions (locked)

### Captain pick (2026-10-16)
- Stepper direction: **D · Capsules**. Each value is a full-width pill: round minus on the left,
  value and unit in the middle, round plus on the right; the name and range sit above the pill on
  one line, with the limit message in place of the range when a limit is hit. The pressed button
  fills with the foreground colour.
- Placement: **P5 · Center card, before you start**, with the "Ask before each session" switch.
- Limits: **proposed**. Focus 5-90 min, Break 5-30 min, both step 5; Rounds 1-12 step 1.

### Review rounds
- Round 1 (captain): the popover "feels off"; wanted it on a side like Sounds and Customize. Board
  answered with P1 (right panel, own page in the Customize shell); superseded by round 2.
- Round 2 (captain): settings in the middle, popping up when the user is about to start. Agreed
  with one guard rail: only on a fresh start, never on resume or round skips, plus an opt-out.

### When the start card opens
- "Fresh" means: not running, `isWorking`, `currentSession === 1`, `timeLeft === workDuration`.
  "Finished" means the last round has run out (`currentSession === sessions`, `timeLeft === 0`).
- On fresh or finished, Play (button) and Space (`useTimerKeyboard`) open the start card instead
  of starting, unless the switch is off. Both entry points must call one shared "request start"
  function so the rule lives in one place.
- Resume from pause, skip to next/previous, and R (reset current block) never open it. Reset on
  round 1 makes the session fresh again, so the next Play opens it.
- Start applies the card values, resets to a fresh round 1 (needed when finished or values
  changed), then starts. Enter triggers Start; Esc and Cancel close and leave the timer untouched.

### Card content
- Start mode: title "Start a session", sub line "Ends around <local time> · Enter to start"
  (start time + rounds x (focus + break) - break), the three capsule steppers under a "Session"
  section header with the live total, the existing `AlarmPicker` as the next section, and a foot
  with the switch on the left, Cancel (ghost) and Start (primary, play icon) on the right.
- Edit mode (footer button): title "Session settings", sub line "Saving restarts the timer",
  same body, foot Cancel and Save. Save keeps today's confirm dialog while a session is in
  progress (not fresh). On a fresh session Save needs no confirm.
- Changes in the card are local until Start or Save; Cancel discards them.

### Persistence
- Signed-in: Start and Save both persist durations and rounds through `useSaveUserSettings`
  (PUT then POST fallback). Durations stay stored in seconds.
- The switch is a new boolean column on `sessionSettings` (for example `ask_before_start`,
  not null, default true) with a Drizzle migration, added to the settings route schemas (reuse
  the drizzle-zod schemas in `tables/settings.ts`), and delivered through the existing
  server-fetched-then-hydrate path: `getUserSettings()` in `app/(app)/layout.tsx` ->
  `TimerStoreProvider initialSettings` -> the timer store. No client fetch on mount, no flash.
- Guests (`app/guest/layout.tsx`, `initialSettings={null}`): values apply to the store only, as
  today; the switch is kept in that browser (localStorage, wrapped in try/catch) and defaults on.

### Shell and layout
- One centered card, 400px wide on desktop, `calc(100vw - 32px)` on phones, max height
  `100dvh - 32px` with the body scrolling. Same surface as the Customize inspector and Records
  room (panel surface, hairline border, radius 18, deep shadow), over a dimmed backdrop.
- Built on the existing Radix dialog primitive in `@repo/ui` so focus trap, Esc, aria-modal and
  scroll lock come for free; do not hand-roll a modal.
- Only one surface open at a time: opening the card closes Customize and the Records room, as
  they already close each other.
- The old `SessionSettings.tsx` popover, `SessionSettingsMobile.tsx` drawer and the three
  `components/input/*Input.tsx` files (plus `Counter.tsx` if unused) are removed.

### Stepper behaviour
- One `Stepper` component used three times. `role="spinbutton"` with `aria-valuenow`,
  `aria-valuemin`, `aria-valuemax`, `aria-valuetext` ("25 minutes"), labelled by its name.
- Arrow Up/Right +step, Down/Left -step, Page Up/Down +/-3 steps, Home min, End max.
- Pointer hold repeats after 400ms at 120ms intervals and stops at the limit.
- At a limit the button is `disabled` and the range line becomes the reason ("Minimum 5 min").
- Targets at least 44px on phones.

### Technical constraints
- Biome style (single quotes, no semicolons, 100 col). No new dependencies.
- No test runner in the repo; verification is by running the app (`bun run web`, `bun run api`)
  and exercising the flows in a browser, plus `bun run check` and `bun run turbo:build`. A small
  pure helper (for example the fresh/finished rule and ends-around maths) may get a `bun run`
  one-off check script if the plan wants one.
- Keyboard guard in `useTimerKeyboard.ts` already ignores keys inside dialogs; the card is a
  dialog, so Space inside it does not toggle the timer.

### Resolved after research (planner defaults, flag in the PR)
- The "Ask before each session" switch shows in the foot of both modes, so a user who turned it
  off can turn it back on from the footer button. Changing only the switch saves without a
  restart.
- The card head keeps the board's close X (`aria-label="Close"`), same as Esc and Cancel.
- A confirmed mid-session Save restarts at round 1 and keeps running; a Save on a fresh session
  stays fresh and paused.
- The command menu (`useParsedCommands.tsx`) uses the same limits constant, so both paths agree.
- Stored values outside the new grid (for example 52 min or 20 rounds) are clamped to the
  limits when the card opens and snap to the step in the direction pressed.

### Claude's Discretion
- File and component names, how "request start" is exposed (store action vs hook), how the open
  state is held (store or context), exact motion values, migration name.
</decisions>
