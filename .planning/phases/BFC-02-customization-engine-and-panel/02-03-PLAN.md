## Phase Goal

**As a** focused user on the befocus dashboard, **I want to** open a customize panel and change the
background, type, colour, progress style, density and grain while watching the dashboard react
instantly, **so that** I can make the timer screen feel like mine, then keep it with Apply or throw it
away with Cancel.

<objective>
Slice: as a session runs, the user sees the new default Edge progress bar fill along the bottom of the
screen and the key hints under the digits, and can press Space / R to drive the timer. Setting
`html[data-progress]` to ruler, ink or none switches the design instantly (from devtools for now, from
the Style section once 02-05 lands). Density changes the digit size.

Purpose: CTL-07 and CTL-12, plus the timer half of CTL-08. These are the dashboard surfaces the Style
section will drive.
Output: a rewritten Timer.tsx, a timer CSS module and a keyboard hook; TimerProgressRing.tsx deleted.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-10 | Tampering | useTimerKeyboard | mitigate | Ignore editable targets, modal dialogs, menus, listboxes, modifier keys, repeats and defaultPrevented events, so typing or other shortcuts never reset a running session by accident (integrity of the user's session) |
| T-02-11 | Denial of service | useTimerKeyboard | mitigate | Only `preventDefault` on Space when it is handled, so native scrolling and activation keep working everywhere else; the listener reads the store with getState and never re-binds per tick |
| T-02-12 | Tampering | timer-progress.module.css | accept | An unknown data-progress value simply matches no rule (no progress shown); the attribute is only written from the Zod-validated Look, and client-side tampering affects only the tamperer |
| T-02-13 | Information disclosure | role=timer readout | accept | It exposes only the countdown already visible on screen |
</threat_model>
