## Phase Goal

**As a** focused user on the befocus dashboard, **I want to** open a customize panel and change the
background, type, colour, progress style, density and grain while watching the dashboard react
instantly, **so that** I can make the timer screen feel like mine, then keep it with Apply or throw it
away with Cancel.

<objective>
Slice: whenever the user opens Customize, the timer glides out of the panel's way. On desktop it
shrinks in place (or moves left of the feather on narrow screens), and on mobile it rises above the
sheet. The user always sees the live preview on the timer they are styling. Closing glides it back.

Purpose: UX-05, "the panel does not obstruct the timer to the point of unusability at any supported
viewport", using the D-20 formula and the UI-SPEC narrow-desktop fallback.
Output: a pure transform function with runnable assertions, and the Timer wiring.
</objective>

- Root `div`: `relative z-0 flex h-[70vh] items-center justify-center font-display text-dash`,
  with an inline `--progress`. It is never transformed, so its `getBoundingClientRect()` gives the
  untransformed timer centre.
- Child `div[data-timer-clock]`: `absolute inset-0 flex items-center justify-center`. This is the
  transform target. It holds both digit blocks and the desktop `.under` block (ruler + key hints).
- Two digit blocks, each with the module class `digits` and `data-timer-digits`: desktop
  (`hidden sm:flex`) and mobile (`sm:hidden`). Exactly one is visible (`offsetParent !== null`).
  `offsetWidth` / `offsetHeight` are layout sizes, unaffected by the transform. They already include
  density (`--timer-scale`) and the user font.
- The edge track and fill (`data-edge-progress`) are siblings outside the clock and are never
  transformed.
- `html[data-panel='open']` hides the key hints (02-03 CSS).

From plan 02-01: `useCustomizeStore(s => s.panelOpen)` is available inside Timer (the
CustomizeStoreProvider wraps the page on both / and /guest). `apps/next/src/lib/customize/customize.check.ts`
is a `node:assert/strict` script, run from apps/next with `bun run src/lib/customize/customize.check.ts`.
It prints `customize.check OK`.

Geometry contract (UI-SPEC "Timer scale while the panel is open", D-20):
- Desktop (vw >= 1024): `featherStart = vw - 520`, `gutter = 24`,
  `centered = min(.72, (featherStart - vw/2 - gutter) * 2 / timerW)`. If `centered >= .4` the result
  is `{ tx: 0, ty: 0, scale: centered }`. Otherwise it is
  `{ tx: featherStart/2 - vw/2, ty: 0, scale: min(.72, (featherStart - 2*gutter) / timerW) }`.
- Mobile (vw < 1024): `sheetH = .6 * vh`,
  `scale = min(.72, (vh - sheetH - 40) / timerH)`, `ty = (vh - sheetH)/2 - centerY`, `tx = 0`. The board
  used `-sheetH/2`, which assumes the timer centre sits at vh/2. The measured centre is exact.

|-----------|----------|-----------|-------------|-----------------|
| T-02-24 | Tampering | Timer inline transform | accept | Inputs are browser layout numbers, not user strings; the template only interpolates numbers into `translate()`/`scale()`, so there is no CSS injection surface |
| T-02-25 | Denial of service | resize/ResizeObserver loop | mitigate | Observers exist only while the panel is open and are cleaned up on close/unmount. The observed digit size is transform-independent, so setting the transform cannot re-trigger the observer |
