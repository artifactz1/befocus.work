## Typography

Panel chrome (always Inter Tight, neutral foreground, per D-14 - never the user's `--font-display` or `--user-accent`):

Three sizes and two weights, collapsed from the board's 11.5-16px spread so the panel has a clear scale. The board's visual result is kept: every board value moves by 1px or less.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Panel heading (`Customize`) | 16px | 600 | 1.3 (letter-spacing -.01em) |
| Label: section chips, group labels (`.fs > .lab`, no uppercase, no tracking in D), segment options, buttons, current-look name, empty-state text | 13.5px | 500 (600 on the selected chip, the current-look name and Apply) | 1.3 |
| Small: hints, "Previewing changes" state, font-card names, range output values (mono) | 12px | 500 | 1.45 (mono output: 1) |

Exempt: the font-card sample "17:42" renders at 30px / 700 in the card's own family. It is a preview of user content, not panel chrome.

The primary visual anchor of the dashboard is the timer. Every panel rule (centered scaling, hints hiding, chrome fading under the feather) exists to keep the timer the focal point while editing.

Dashboard-facing type (what `--font-display` controls, `CTL-04`): the timer digits and session title switch families; sizes are unchanged by this phase (existing `25vw`/`cqw`-based responsive sizing stays). Do not introduce new font sizes for the dashboard in this phase - only the family changes.

## Panel Shell Contract (D-20, Direction D - Feathered Dock)

This is the accepted, locked visual design. Source of truth: `.lavish/customize-panel-directions.html`, rules under `.stage[data-dir="D"]` and `.m[data-dir="D"]`. Values below are transcribed exactly, not approximated.

### Desktop (aside, ≥ the breakpoint where a 520px dock is viable - see Viewport Contract for the 1024px risk)

- Container: `position: fixed` (or absolute within the dashboard root), `top: 0; right: 0; bottom: 0`, `width: 520px`. No border, no border-radius, no box-shadow.
- `padding-left: 120px` (feather zone) so the opaque controls column is exactly `520 - 120 - 28(right padding) = 372px`.
- Background: `linear-gradient(90deg, transparent, var(--panel-surface) 120px)`.
- `::before` pseudo-element: `position: absolute; left: 0; top: 0; bottom: 0; width: 150px; backdrop-filter: blur(10px); mask: linear-gradient(90deg, transparent, #000 80%, transparent)` - this is what makes the dashboard visually blur *into* the panel rather than being cut off by an edge.
- Open transition: `transform: translateX(40px) → translateX(0)`, `opacity`, over `450ms cubic-bezier(.2, .7, .2, 1)`; `background-color` also transitions `.35s` so the surface re-tints smoothly when the previewed background changes.
- Header (`p-head`): `padding: 30px 28px 10px 0`. Heading `16px / 600 / -.01em`.
- Section chips (`tabs`): no bottom border, `gap: 4px`, `padding: 6px 28px 12px 0`; each chip `border-radius: 10px; padding: 7px 11px`; selected chip background is `--panel-lift` (a filled pill, not an underline).
- Body (`p-body`): `padding: 4px 28px 24px 0; gap: 10px`.
- Control groups (`.fs`): `background: var(--panel-soft); border-radius: 18px; padding: 14px 16px 16px; gap: 12px`. Group label uses the Label role (13.5px/500), no uppercase/tracking (this overrides the generic `.fs > .lab` uppercase style used elsewhere).
- Segmented controls (`.seg`): track `background: rgb(0 0 0 / .22); border: 0; border-radius: 12px`; selected segment `border-radius: 9px; background: var(--panel-lift); box-shadow: 0 6px 16px -8px rgb(0 0 0 / .7), inset 0 0 0 1px var(--panel-hair)`.
- Pick cards (font cards, curated theme cards): `border: 1px solid var(--panel-hair); background: transparent; border-radius: 14px`; selected: `border-color: transparent; background: var(--panel-lift); box-shadow: 0 14px 30px -14px rgb(0 0 0 / .8), inset 0 0 0 1px rgb(255 255 255 / .12)`.
- Swatch (solid/accent) selection ring: `box-shadow: 0 0 0 2px var(--panel-surface), 0 0 0 4px hsl(var(--foreground))`.
- Current-look row (Theme section): `background: var(--panel-lift); border: 0; border-radius: 14px; padding: 8px 14px 8px 8px`, same lifted shadow as pick cards.
- Empty state (Theme section): `border: 1px solid var(--panel-hair); border-radius: 14px; background: transparent` (Direction D drops the generic dashed border in favor of a solid hairline).
- Footer (`p-foot`): **no divider line.** `border-top: 0; padding: 18px 28px 26px 0; background: linear-gradient(0deg, var(--panel-surface) 70%, transparent); margin-top: -18px; position: relative` - scrolling content fades out under the footer instead of a hard rule. Layout: Reset on the left, Cancel + Apply on the right (D-20).
- Content stagger on open / section switch: every direct child of `p-body` animates in with `bf-in` (`opacity 0→1, blur(6px)→0, translateY(6px)→0`, `500ms cubic-bezier(.2,.7,.2,1)`), staggered top-down: child 2 delays 60ms, child 3 120ms, child 4 180ms, child 5+ 240ms (capped - no further stagger past the 5th child).
- "Previewing changes" dot: pings once (`bf-ping`, `0.9s ease-out`, `box-shadow 0 0 0 0 accent-60% → 0 0 0 9px transparent`) the moment the preview first becomes dirty. Does not repeat on subsequent edits in the same session.
- Wordmark and menu: no separate opacity/fade rule exists for them - they simply sit inside the feather zone, so the gradient + blur alone de-emphasize them. Do not add an opaque card over them.

### Timer scale while the panel is open (desktop)

Formula (D-20): `scale = min(0.72, (panelFeatherStart - viewportCenterX - gutter) * 2 / timerWidth)`, where `panelFeatherStart = viewportWidth - 520`. Confirmed reference points: **≈0.42 at 1440×900**, **cap of 0.72 reached at 1920×1080** (the timer is sized from viewport height, so available width headroom grows faster than the timer at wide aspect ratios).

`gutter` is not specified in CONTEXT - Claude's Discretion, resolved here: **`gutter = 24px`**.

**Narrow-desktop fallback (Claude's Discretion, flagged to the owner in the PR):** the centered formula only works while the feather starts right of the viewport center. At 1024×640, `panelFeatherStart = 1024 - 520 = 504px`, which is left of `viewportCenterX = 512px`, so the raw output goes negative and any floored scale would leave the timer under the blurred feather. Rule: compute `centeredScale` with the formula above. **If the centered rendered width `(panelFeatherStart - viewportCenterX - gutter) * 2` is at least 336px** (a margin under the 352px the owner reviewed at 1440×900, so that size never flips; the threshold is in pixels because the real timer is wider than the board's, which pushed a 0.4 scale threshold past 1440), the timer stays centered in the viewport and scales to `centeredScale`. **Otherwise** the timer centers in the free area left of the feather: `translateX = panelFeatherStart / 2 - viewportCenterX` and `scale = min(0.72, (panelFeatherStart - 2 * gutter) / timerWidth)`. At 1024×640 that gives about `translateX(-260px)` at the 0.72 cap. The switch sits at about 1423px wide at any height. Neither the feather nor the opaque 372px column may ever overlap the timer. The executor verifies 1024×640, 1280×800, 1440×900 and 1920×1080 explicitly.

### Mobile (`m[data-dir="D"]`, vaul `drawer`, `modal={false}`, no overlay - D-11, D-20)

- Sheet height: `60%` of viewport height (`--sh` var, no scrim).
- `padding-top: 34px` (feather zone at the top instead of the left).
- Background: `linear-gradient(180deg, transparent, var(--panel-surface) 64px)`.
- `::before` mask band: `top: 0; height: 48px; mask: linear-gradient(180deg, transparent, #000 70%, transparent)`.
- Drag handle (`grab`): `margin-top: 0` (vaul's built-in handle sits flush at the top of the feather).
- Header `padding: 8px 16px 6px`; tabs `padding: 4px 16px 10px`; body `padding: 2px 16px 20px`; footer `padding: 16px 16px 20px`.
- While open: header, edge progress and footer transport chrome fade to `opacity: 0` (existing shared `.m.open` rules) - same "the dashboard is the preview" principle as desktop's non-modal aside.
- Timer rises and scales into the 40% of viewport above the sheet: `scale = min(0.72, (viewportHeight - sheetHeight - 40) / timerHeight)`. At 390×844 (`sheetHeight ≈ 506px`), this resolves to the `0.72` cap - confirmed no floor issue on the reference mobile viewport.

## Motion & Reduced Motion

| Interaction | Timing | Reduced-motion behavior |
|---|---|---|
| Aside slide-in / slide-out | `translateX(40px→0)` + opacity, `450ms cubic-bezier(.2,.7,.2,1)` | Instant (no transform transition) |
| Timer scale on panel open/close | same `450ms cubic-bezier(.2,.7,.2,1)` on `.center` | Instant |
| Section content stagger (`.rv` / `bf-in`) | `500ms cubic-bezier(.2,.7,.2,1)`, 60ms steps, capped at 5th child | Disabled entirely - content appears at final state with no blur/translate |
| "Previewing changes" dot ping | one-shot `0.9s ease-out` | Disabled entirely |
| Key hints fade (D-16/D-20) while panel open | `opacity` `250ms` | Kept (short, non-distracting; not gated by reduced motion in the board CSS) |
| Chrome focus-fade while a session runs (D-17) | fade to 0 after **2000ms** idle, `800ms ease` fade transition, re-armed on pointermove/keydown/focus-within with an **1800ms** re-arm cooldown (Claude's Discretion - exact numbers taken directly from the prototype's own idle-timer implementation, not invented) | Unaffected - this is a visibility state, not a motion effect users would disable |
| Panel surface background-color transition (follows previewed `--bg-solid`) | `350ms` | Kept |

All durations above come directly from the board's own `@media (prefers-reduced-motion: reduce)` block and D-20's prose ("Both the stagger and the ping are off... the slide and timer scale become instant").

## Accessibility Contract (UX-06, D-11, D-12)

- Panel: `role="dialog" aria-modal="false"`, labelled by its heading (`aria-labelledby` → the `Customize` `<h4>`/`<h2>`). No scrim, ever (D-11) - dimming the dashboard would falsify the live preview.
- Focus management: opening the panel moves focus to the panel heading; closing (by any method - close button, Esc, Cancel, re-clicking the trigger, or route change) returns focus to the trigger button.
- Tab order: confined to the panel only on mobile, where the sheet visually covers the dashboard chrome. On desktop, the dashboard behind the feather stays keyboard-reachable (nothing is `inert`), since D-11 stops short of trapping focus at that breakpoint.
- Sections are ARIA tabs: `role="tablist"` (labelled `Customize sections`), each chip `role="tab" aria-selected` with `tabindex` following the roving-tabindex pattern (selected = `0`, others `-1`), body panel `role="tabpanel"` labelled by the active tab. Arrow-left/right cycle sections with wraparound (matches the prototype's existing keydown handler).
- Every swatch (solid, accent) is a labelled native radio (`aria-label="Accent #hex"` or the swatch name) inside a `<span>` visual, not a bare colored `<div>` with a click handler.
- Segmented controls (progress, density, background source) are native radios inside `role="radiogroup"` with an accessible group label.
- Sliders (overlay opacity, blur, contrast, grain) are native `<input type="range">` with an associated `<label>` and a live `<output>` reflecting the current value.
- Global key handlers (Space = play/pause, R = reset, per D-12/D-18): attached on `window`, must check `event.target` is not a text input, color input, radio, or range control before acting, and must ignore any event carrying a modifier key (Cmd/Ctrl/Alt/Shift). This lets the dashboard stay "live" behind the open panel without stealing keystrokes meant for a form control.
- Numbered section shortcuts (`1`-`5` to jump sections while the panel is open): explicitly out of scope for Phase 2 per the design board ("left out of the demo") - do not build this now.
- Density/contrast/grain changes must not, at any setting, drop text below WCAG-reasonable legibility. `--text-contrast` floor of `0.55` (not `0`) exists specifically to prevent an unreadable dashboard (D-04).
