## Phase Goal

**As a** focused user on the befocus dashboard, **I want to** open a customize panel and change the
background, type, colour, progress style, density and grain while watching the dashboard react
instantly, **so that** I can make the timer screen feel like mine, then keep it with Apply or throw it
away with Cancel.

<objective>
Slice: the user starts a session and watches the dashboard get out of the way. The session grid fills
in the accent, and the header and footer fade out after two seconds, coming back on a mouse move or key
press. The menu buttons are quiet and bare, and header/footer spacing follows density.

Purpose: CTL-11 and CTL-13, plus the chrome half of CTL-08.
Output: a restyled SessionsUI, a chrome-idle hook, density-aware Header/Footer, and bare MenuButtons
across the dashboard.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| user input events → idle state | pointer / key events toggle a document attribute |
| html attributes → CSS | data-chrome-idle, data-panel and data-density are read by CSS only |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-14 | Denial of service | useChromeIdle | mitigate | Only write the attribute on state change, use passive listeners, remove all listeners and timers on cleanup and when the timer stops, so a long session never leaks timers or thrashes layout |
| T-02-15 | Spoofing (UI) | faded chrome | mitigate | Chrome returns on any pointer, wheel or key event and on visible keyboard focus, and never fades while the panel is open, so controls are never invisible while being operated |
| T-02-16 | Tampering | MenuButton props | accept | Presentation-only change; `variant` is removed from the type so misuse is a compile error |
| T-02-17 | Information disclosure | session grid | accept | Shows only session progress already visible on screen |
</threat_model>
