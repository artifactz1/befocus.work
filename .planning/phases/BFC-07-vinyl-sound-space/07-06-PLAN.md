## Phase Goal

**As a** signed-in BeFocus user, **I want to** paste a YouTube link into my room and keep it as a record
or ambience, **so that** my room holds the sounds I actually focus to.

both sides of the boundary, plus per-item Rename and Delete in the room, replacing the removed
AddSoundButton and delete mode.

Output: youtube.ts validator used by API and client, AddSoundDialog.tsx, SoundOptions.tsx, paste
listener, guest footnote.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| clipboard -> paste listener | Arbitrary text from the user's clipboard |
| browser -> POST/PUT /user/sounds | Client validation can be bypassed |
| youtube.com oEmbed -> dialog | Third-party JSON (title) |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-07-15 | Tampering | insertSoundSchema / updateSoundSchema | mitigate | `url.refine(isYouTubeUrl)` with URL parsing, exact host allowlist and protocol check on the server; length caps on url (2048), name (80), id (64) |
| T-07-16 | Tampering | paste listener | mitigate | Same isYouTubeUrl at the paste boundary before any dialog or request; javascript: and look-alike hosts rejected (check script cases) |
| T-07-17 | Information disclosure (XSS) | oEmbed title, stored names | mitigate | Title only set as an input value and rendered as React text; no dangerouslySetInnerHTML in components/records (grep gate) |
| T-07-18 | Elevation of privilege | PUT /user/sounds rename, DELETE | mitigate | Update and delete are scoped by and(id, userId) (07-01 and existing handler); options UI hidden for guests and requireAuth gates the routes |
| T-07-19 | Spoofing | guest add | mitigate | Client gates on session; server requireAuth returns 401 regardless |
| T-07-20 | Information disclosure | oEmbed request | accept | Sends the pasted url to youtube.com, which the user is already adding to a YouTube player |
</threat_model>
