## Phase Goal

**As a** person focusing with BeFocus, **I want** the record room to look and feel like the rest of the
app (the Customize inspector), and **I want** my records to look like mine, **so that** the room is calm
to use and personal.

Rebuild the record room as Direction A "Quiet Deck" from the second design board
(`data/befocus-records-design/report.md`, board section 03), with the owner's round 3-5 changes, and add
per-record vinyl customisation backed by new sound columns and an owner-scoped label image bucket.

Output: new sound fields and migration, label upload/read routes on R2, a rebuilt room, chip, add dialog
and Records button, refreshed PR screenshots.

## Decisions (owner, 2026-10-15)

- Direction A, timer centred, room is a left 400px card (desktop) or a bottom sheet (phone).
- Vinyl customisation lives in the add dialog: label Auto, 7 swatches, video thumbnail, upload image;
  disc finish Black, Smoke or Tinted. No inner ring on any disc.
- The add dialog shows the square album cover with the disc sliding out and spinning; off under reduced motion.
- Label pictures may be the video thumbnail or an uploaded image. The upload bucket is the one exception
  to "Phase 5 storage out of scope"; audio stays YouTube only.

## Tasks

### Task 1: sound fields and validation

- `sounds` gains `label_color` (text, null = Auto), `label_image` (text, null | 'thumbnail' | 'upload')
  and `disc_finish` (text, not null, default 'black'). Migration 0009 via drizzle-kit generate.
- Insert and update schemas accept `labelColor` (`#rrggbb` or null), `labelImage` (`thumbnail` or null;
  `upload` is only set by the upload route) and `discFinish`.
- Client `ServerSound`, store `Sound` and `reconcileSounds` carry and compare the new fields.
- Verify: `sounds.check.ts` covers the new reconcile cases and schema validation.

### Task 2: label image bucket

- R2 binding `LABELS` (bucket `befocus-labels`) in `wrangler.toml`; `LABELS` in the worker env schema.
- `PUT /user/sounds/:id/label`: owner check, `image/jpeg|png|webp` only, at most 1 MB, key
  `labels/{userId}/{soundId}`, sets `label_image = 'upload'`.
- `GET /user/sounds/:id/label`: owner-scoped read, `Cache-Control: private`.
- Deleting a sound deletes its label object. The client resizes to a 512px square webp before upload.
- Routes follow the three-file split and are chained in `user.index.ts` so they are on the typed client.
- Verify: curl with and without a session, wrong type, too large, another user's id.

### Task 3: the room

- Card and sheet per the board; remove the desktop timer shift; phone keeps the timer above the sheet.
- Floating vinyl (`Vinyl` component shared by deck, shelf, chip and dialog), hairline arm, transport row,
  ambience slider rows, square-sleeve shelf, options visible on touch and focus.
- Auto label follows the accent, mixed per name, replacing the saturated hashed inks (J4).

### Task 4: chip, Records button, add dialog

- Desktop pill above the footer aligned with the controls; phone Records icon shows a spinning vinyl with a
  caption. Records button active state is a 40px soft circle.
- Add dialog per the board (centred card, bottom sheet under 640px), Record/Ambience choice kept, label and
  disc options for records only, live preview. Rename keeps its own small dialog.

### Task 5: verify and ship

- `bun run check`, `bun run turbo:build`, `sounds.check.ts`, dev servers driven at 1440x900 and 390x844.
- Re-take PR screenshots, update PR #116, write 07-08-SUMMARY.md, run the verifier.

Phases 8-10, other Phase 5 storage, non-YouTube audio, the unrelated current-UI observations in the report.
