## Pattern Assignments

### `apps/next/src/lib/server/getUserSettings.ts` (utility, request-response) - FND-01, D-09

**Current state, full file (1-40):**
```typescript
'use server'

import { betterFetch } from '@better-fetch/fetch'
import type { Settings } from '@repo/api/db/schemas'
import { env } from '@repo/app/env/next'
import { cookies } from 'next/headers'

export async function getUserSettings(): Promise<Settings | null> {
  // NOTE: example of getting session
  // const reqHeaders = await headers()
  // ...
  const cookieStore = await cookies()
  const cookieHeader = cookieStore.get('better-auth.session_token')

  if (!cookieHeader) return null

  const { data: settings } = await betterFetch<Settings>(`${env.API_URL}/user/settings`, {
    headers: {
      cookie: `better-auth.session_token=${cookieHeader.value}`,
    },
  })

  if (!settings) {
    console.error('Failed to fetch user settings', settings)
    return null
  }

  return settings
}
```

**The bug (D-09):** line 24 (`cookieStore.get('better-auth.session_token')`) and line 30
(`` `better-auth.session_token=${cookieHeader.value}` ``) hardcode the non-secure cookie name.
better-auth's `advanced.defaultCookieAttributes.secure: isProduction` in
`packages/api/src/lib/middlewares/auth/create-better-auth-config.ts:50` means the cookie is
actually named `__Secure-better-auth.session_token` in production - `cookieStore.get(...)` misses
it and the function silently returns `null` (built-in defaults render, no error).

**No other server-fetch helper exists in the repo to copy from** - this is the sole file under
`apps/next/src/lib/server/`. The fix has to be authored fresh. The already-commented-out line 10
(`const reqHeaders = await headers()`) is the only hint in the codebase that `next/headers`
`headers()` (not `cookies()`) exposes the raw `Cookie` header string via
`(await headers()).get('cookie')` - that is the natural way to satisfy D-09's "forward the incoming
request's Cookie header as-is" requirement without hardcoding any cookie name.

**Early-return pattern to keep (D-08):** the existing `if (!cookieHeader) return null` /
`if (!settings) { console.error(...); return null }` shape is exactly the "no client fallback
fetch, log server-side, render defaults" behavior D-08 asks for - preserve this shape, just widen
what counts as "no cookie" and "fetch failed".

store to hold real values *during* the server render, not after an effect.
