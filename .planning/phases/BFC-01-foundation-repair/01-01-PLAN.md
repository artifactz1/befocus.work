Current apps/next/src/lib/server/getUserSettings.ts (the bug is the hardcoded cookie name):
```typescript
'use server'
import { betterFetch } from '@better-fetch/fetch'
import type { Settings } from '@repo/api/db/schemas'
import { env } from '@repo/app/env/next'
import { cookies } from 'next/headers'

export async function getUserSettings(): Promise<Settings | null> {
  const cookieStore = await cookies()
  const cookieHeader = cookieStore.get('better-auth.session_token')
  if (!cookieHeader) return null
  const { data: settings } = await betterFetch<Settings>(`${env.API_URL}/user/settings`, {
    headers: { cookie: `better-auth.session_token=${cookieHeader.value}` },
  })
  if (!settings) { console.error('Failed to fetch user settings', settings); return null }
  return settings
}
```

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> Next server | Incoming Cookie header is attacker-controllable |
| Next server -> API | Next forwards the user's session cookie server-to-server |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-01-01 | Information Disclosure | getUserSettings cookie forwarding | mitigate | Destination URL is built only from `env.API_URL` (Zod-validated server env); no request-derived host/path, so cookies cannot be forwarded to another origin |
| T-01-02 | Information Disclosure | getUserSettings error logging | mitigate | Log only `{ status }`; never log cookie header, request headers or response body |
| T-01-03 | Elevation of Privilege | `'use server'` export of getUserSettings | mitigate | Remove `'use server'` so the helper is not a publicly invokable Server Action endpoint |
| T-01-04 | Spoofing | forwarded session cookie | accept | API validates the session via better-auth on every request; Next only relays the caller's own cookie, so a forged cookie gets a 401/404 and null settings |
| T-01-05 | Tampering | repro-only NODE_TLS_REJECT_UNAUTHORIZED=0 | mitigate | Set only on the local dev command line; never written to env files or committed (acceptance: no tracked env file changes) |
</threat_model>
