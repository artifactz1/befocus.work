## Phase Goal

**As a** signed-in person running focus sessions, **I want to** have my block records stored with
my account, **so that** my focus history is kept beyond this browser.

<objective>
Seventh slice: the server side of block records. A `focus_blocks` table (migration generated by
drizzle-kit, applied by the human), and PUT /user/blocks: a batch of up to 100 records validated by
08-01's shared `blockRecordSchema`, upserted by id and scoped to the session user. No read route
in this phase (nothing in Phase 8 reads server records; Phase 10 owns history views).

Purpose: BLK-03 / BLK-04 for accounts: the record exists server-side with all its fields and is
idempotent under retries and re-runs.
Output: table, schemas barrel export, generated migration, route trio, check script, app.ts
wiring, and a human confirmation that the migration is applied.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-21 | Spoofing | PUT /user/blocks | mitigate | requireAuth gates the path and the handler returns 401 without c.get('user'); the owner is always user.id, never a body field |
| T-08-22 | Elevation of privilege / Tampering | upsert on client-chosen ids | mitigate | onConflictDoUpdate setWhere eq(focusBlocks.userId, user.id) and no userId in the update set, so another user's row with the same id is never changed (ASVS V4 access control) |
| T-08-23 | Tampering | body fields | mitigate | Strict blockRecordSchema at the route (uuid ids, enums, int bounds, epoch window, startedAt <= endedAt); defaultHook answers 422 (ASVS V5 input validation) |
| T-08-24 | Denial of service | body size and count | mitigate | bodyLimit 64 KB answers 413 before parsing; at most 100 records per request; one insert statement per request |
| T-08-25 | Tampering | production schema | mitigate | Migration generated only; applied by the human in Task 3; agents never run migrate, push or SQL |
| T-08-26 | Information disclosure | error responses | mitigate | 500 returns a generic message; details go to console.error only |
| T-08-27 | Repudiation | record writes | accept | Rows carry created_at / updated_at; no audit log for personal timing data |
</threat_model>
