# Phase 08 - UI Design Contract: Focus Blocks and Added Time

> Visual and interaction contract for the ended state, adding and removing time, and the
> extended progress. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

Source of truth: the captain's picks in `08-CONTEXT.md` (1D, 2D, 3A, 4C) and the approved mocks in
`.lavish/phase8/board.html` (worktree 1, untracked). The board's option 3C `--overtime` colour was
rejected and is **not** used. Where this spec decides something the picks left open, it is marked
**(spec decision)**. No questions were asked; every value below comes from CONTEXT, the board, or
an existing token.

Viewports this contract is written for: desktop 1440x900, phone 390x844, and the breakpoints the
timer already uses: `max-width: 639px` (phone stacked digits), `max-width: 1023.98px` (sheet and
strip mode), footer widths at `md` 768 / `lg` 1024 / `xl` 1280.

## Footer transport (1D)

Four buttons in every state, same slots, same widths, same order. Only the outer pair changes.
Slot widths are today's `MenuButton` sizes: phone ~58x40, `md` 64x40, `lg` 96x48, `xl` 128x48.
Container unchanged: `flex items-center justify-center gap-1 px-2 py-1.5`.

### States

| State | Slot 1 | Slot 2 | Slot 3 | Slot 4 |
|-------|--------|--------|--------|--------|
| Idle (before Start) | Back (`SkipBack`) | Play | Reset | Next (`SkipForward`) |
| Running | **−1** (text) | Pause | Reset | **+1** (text) |
| Running, under 1:00 left | **−1** dimmed, `aria-disabled` | Pause | Reset | +1 |
| Running, hold tray open on −1 | −1 in held look, tray above | Pause | Reset | +1 |
| Running, hold tray open on +1 | −1 | Pause | Reset | +1 in held look, tray above |
| Paused | Back | Play | Reset | Next |
| Ended (00:00) | **−1** dimmed, `aria-disabled` | **Play** dimmed, `aria-disabled` | Reset (live) | **+1** (live) |
| Ended, hold tray open on +1 | −1 dimmed | Play dimmed | Reset | +1 held, tray above (all add amounts live) |

Notes:

- Running covers focus and break blocks alike (Q5). Paused blocks cannot be adjusted.
- −1 dims whenever 1 minute is at or above the time left (`timeLeft <= 60`), re-evaluated every
  tick, so a focused −1 dims in place as the clock crosses 1:00.
- Adding at 00:00 resumes the same block (ended -> running). The footer then shows the Running
  row immediately; after +1 the time left is exactly 1:00, so −1 is dimmed (consistent rule).

### Button looks

| Look | Value |
|------|-------|
| Base | Today's outline: `border border-border` (hsl 0 0% 25%), `rounded-md`, transparent fill |
| −1 / +1 text | `font: 600 16px/1 var(--font-app)`; 14px under `max-width: 639px`; `font-variant-numeric: tabular-nums`. Visible text uses U+2212 minus: "−1", "+1" |
| Held (pointer down on −1 / +1, and while its tray is open) | `background: rgb(255 255 255 / 0.12); border-color: rgb(255 255 255 / 0.28)` (board `.btn.held`) |
| Dimmed (`aria-disabled="true"`) | `opacity: 0.3; cursor: default`; hover and active looks suppressed; click and keyboard activation are no-ops |
| Focus | Unchanged: `focus-visible:ring-2 ring-ring ring-offset-2` |
| Hold support (−1 / +1 only, running or ended) | `touch-action: none; user-select: none; -webkit-user-select: none; -webkit-touch-callout: none`; `contextmenu` prevented so a long press never opens the OS menu |

**(spec decision)** State-driven disables use `aria-disabled="true"`, not the native `disabled`
attribute. Native `disabled` drops focus to `<body>` when the focused −1 dims at 1:00 or the
focused Pause becomes the dimmed Play at 00:00. With `aria-disabled` the button keeps focus,
stays in the tab order, and announces as dimmed. The board's 0.3 opacity is used, not
`button.tsx`'s `disabled:opacity-50`.

### Tooltips

Existing Radix tooltips stay. Tooltip is forced closed (`open={false}`) while a hold is in
progress, while that button's tray is open, and on any `aria-disabled` button.

## Hold tray (2D)

### Gesture

| Input | Result |
|-------|--------|
| Tap (pointer down and up within 400 ms, pointer stayed on the button) | Apply 1 minute. Presses stack. |
| Pointer down 400 ms on −1 / +1 | Tray opens above the button. Pointer captured on the button. No amount applied yet. |
| Leave the button, or `pointercancel`, before 400 ms | Hold cancelled. Nothing applied. |
| After opening: slide onto an amount | That cell shows the active look |
| Release over an enabled cell | Apply that amount, close tray |
| Release over a dimmed cell or anywhere off a cell | Nothing applied; tray stays open for a tap |
| Tap an enabled cell (tray already open) | Apply that amount, close tray |
| Escape, or pointer down outside the tray and its button | Close tray, nothing applied |
| Block status leaves running / ended (pause by Space, reset, end) | Close tray, nothing applied |

### Keyboard path to the tray (the hold has a non-pointer path)

| Key, with −1 or +1 focused | Result |
|-----|--------|
| Enter / Space | Apply 1 minute (native button activation) |
| ArrowUp or ArrowDown | Open tray, focus its first enabled cell |
| ArrowLeft / ArrowRight (in tray) | Move between cells (wraps); dimmed cells are focusable but inert |
| Enter / Space (in tray) | Apply the focused cell, close tray, return focus to the trigger |
| Escape / Tab (in tray) | Close tray, return focus to the trigger (Tab then moves on normally) |

The trigger keeps plain button semantics, because Enter and Space apply 1 minute: no
`aria-haspopup` (a menu button would promise that Enter opens the menu). It carries `aria-expanded`,
`aria-controls` pointing to the tray, and `aria-describedby` pointing to visually hidden text
"Arrow Up for 1, 5 or 10 minutes" **(checker fix)**. The tray is `role="menu"` with
`role="menuitem"` cells. `[role='menu']` is in `GUARDED_CONTAINER_SELECTOR` in
`useTimerKeyboard.ts`, so the global handler ignores every key while focus is inside the tray: the
tray component owns Escape, the arrows, Enter, Space and Tab itself. Opened by pointer, focus stays
on the trigger; opened by keyboard, focus moves into the tray.

### Tray layout

| Property | Desktop (`min-width: 1024px` and fine pointer) | Under 1024px or `pointer: coarse` |
|----------|---------|------------------------------------------|
| Position | `position: absolute; bottom: calc(100% + 8px)` of the button's wrapper (`position: relative`) | Same |
| Alignment | −1 tray: `left: 0` (grows right). +1 tray: `right: 0` (grows left). Never runs off-screen. | Same |
| Container | `display: flex; gap: 4px; padding: 4px; border-radius: 12px` | Same |
| Surface | `background: color-mix(in srgb, var(--bg-solid), #fff 5%); border: 1px solid rgb(255 255 255 / 0.08); box-shadow: 0 24px 60px rgb(0 0 0 / 0.5)` | Same |
| Cells | 3 cells, order 1 / 5 / 10 left to right in both trays; each `72x44`, `border-radius: 8px`, `background: rgb(255 255 255 / 0.05)` | `52x44` |
| Cell text | `font: 600 16px/1 var(--font-app); tabular-nums`; "+1 +5 +10" / "−1 −5 −10" (U+2212) | 14px |
| Active cell (slid onto, or focused, or hover) | `background: hsl(var(--foreground)); color: #101010` | Same |
| Dimmed cell | `opacity: 0.3`, `aria-disabled="true"` | Same |
| Stacking | `z-index: 40` (above footer and digits, below dialogs at 50) | Same |
| Focus ring on cells | `outline: 2px solid hsl(var(--ring)); outline-offset: 2px` | Same |

Widths: desktop tray 3x72 + 2x4 + 2x4 + 2 = 234px; phone 174px. Both fit inside 390px from either
footer edge.

### Disabled remove amounts

A remove amount is dimmed when amount x 60 >= time left in seconds, re-evaluated every tick while
the tray is open. At 04:20: −1 live, −5 and −10 dimmed. Under 1:00: all three dimmed (and the
tray cannot be opened by hold, because −1 itself is dimmed). Add amounts are never dimmed.

### First-run hint

- Desktop: the running hints row gains a third item, `<kbd>+</kbd> <kbd>-</kbd> 1 min, hold for
  more`, shown while running until the user first opens a tray (by hold or ArrowUp). Then it is
  gone for good: `befocus.adjustHintSeen` (boolean, `readStored` / `writeStored`, Zod
  `z.boolean()`) **(spec decision on the key name)**. Signed-in and guest alike; browser-only.
- Phone (`max-width: 639px`): nothing extra (CONTEXT).
- The hints row stays `aria-hidden`; the shortcut is exposed on the buttons through
  `aria-keyshortcuts` (see Keyboard).
- Phase 9 seam: Phase 9 replaces `.hints` with the now line during a running focus block. This
  hint lives in the same row and goes with it; nothing else in the running `.under` slot.

## Ended block under the digits (1D, 4C)

### Contents

| Part | Focus block ended | Break ended | Last focus block of the session ended **(spec decision)** |
|------|-------------------|-------------|-------------------------------|
| Label (desktop) | "Focus block done · 25 min" | "Break done · 5 min" | "Focus block done · 25 min" |
| Label (phone) | "Focus block done" | "Break done" | "Focus block done" |
| Primary button | "Start break" | "Start focus" | "Finish session" |
| Hints (desktop) | `<kbd>+</kbd> add 1 min` · `<kbd>Enter</kbd> start break` | `<kbd>+</kbd> add 1 min` · `<kbd>Enter</kbd> start focus` | `<kbd>+</kbd> add 1 min` · `<kbd>Enter</kbd> finish session` |

- The minutes in the label are the block's final length, planned + net added, in whole minutes
  (a 25 min block with +5 reads "30 min").
- "Finish session": the last focus block has no next block, so "Start break" would lie. It records
  `finished` and takes today's path to `SessionCompleteModal` (unmodified). The button label
  follows the kind of the next block in `blocks[]`; no next block means "Finish session".
- Start break / Start focus records `finished`, moves to the next block and starts it running.

### Desktop and tablet (`min-width: 640px`)

Lives in `.under` (anchored at `top: calc(50% + var(--digit-size) / 2)` plus today's margin).

```
                  0 0 : 0 0          (breathing)
            FOCUS BLOCK DONE · 25 MIN          label
                 [  Start break  ]             primary, 44 tall
           [+] add 1 min   [Enter] start break hints
```

| Property | Value |
|----------|-------|
| Group | `display: grid; justify-items: center; gap: 16px`. While ended it replaces the running children of `.under` (ruler, hints) and is the only child, so `.under`'s 18px gap never applies inside it; 16px governs label to button to hints |
| Label | `font: 500 14px/1 var(--font-mono); letter-spacing: 0.14em; text-transform: uppercase; color: color-mix(in srgb, var(--fg) 55%, transparent); white-space: nowrap` |
| Primary | `height: 44px; padding: 0 20px; border: 0; border-radius: 8px; background: hsl(var(--foreground)); color: #101010; font: 600 16px/1 var(--font-app)`; hover `hsl(var(--foreground) / 0.9)`; focus `outline: 2px solid hsl(var(--ring)); outline-offset: 2px`. No icon. `aria-keyshortcuts="Enter"` |
| Hints | The existing `.hints` row style (15px mono, 13px kbd), `aria-hidden`, `bf-chrome` |
| Ruler in the ended state | **Hidden (spec decision).** The board's ended mocks show no ruler, the block is complete, and ruler + label + button + hints (~160px) overlaps the footer at 1440x900. Edge and Ink stay visible because they live outside `.under`. |

Height fit, checked against footer buttons with at least 16px clearance:

| Viewport | Rule |
|----------|------|
| Height 800px and up | Label, button, hints |
| `max-height: 799px` | Hints row hidden in the ended state (the Start button keeps `aria-keyshortcuts`) |
| `max-height: 559px` (phone landscape) | Label hidden too; button only. The live region carries the label text. |

The planner verifies no overlap at 1440x900, 1280x720, 1024x768 and 844x390.

Record room open on desktop (`min-width: 1024px`, stage scaled 0.8): the ended group stays,
hints fade as today.

### Phone (`max-width: 639px`)

The phone digits are stacked (MM over SS) and there is no `.under` today. Follows board mock
`q1d-end-p`:

```
        FOCUS BLOCK DONE        label, 16px above the stacked digits
              0 0
              0 0               (breathing)
        [  Start break  ]       own row, centred in the gap above the footer
   [−1] [ > ] [ reset ] [+1]    footer (−1 and play dimmed)
```

| Property | Value |
|----------|-------|
| Label | Same style as desktop at 12px; centred; bottom edge 16px above the top of the stacked digits |
| Primary | Same as desktop but `padding: 0 16px`; still 44px tall (board's 40 raised to the touch minimum) and 16px text |
| Primary position | Centred horizontally; vertically centred between the bottom of the stacked digits and the top of the footer buttons, minimum 12px clearance each side |
| Hints | None |
| DOM order | Label, digits, primary, footer (screen reader and Tab order match the visual order) |

**(spec decision)** CONTEXT says "the label and button get their own row between digits and
footer". At 390x844 the gap between the stacked digits and the footer fits the 44px button but
not label + button, so the label goes above the digits as the board mock draws it. The planner
verifies at 390x844 and 375x667; if the button cannot clear 12px at 375x667, the label hides
under `max-height: 699px` and the live region carries it.

### Sheet open under 1024px (strip mode)

**(spec decision)** No change to the sheet behaviour: under 1024px with the record room or panel
open, `.under` and the footer are hidden (today's rules). The 132px strip shows the breathing
00:00, the tab title and the alarm carry the state, and closing the sheet reveals the ended block.
The digits badge is hidden in strip mode.

## Progress extension (3A)

Total = planned + net added. All three styles rescale to the total. With net > 0 a **notch** marks
the planned end at `planned / total` and the part past it is **hatched**. With net <= 0 there is
no notch and no hatch **(spec decision: no clamping; the badge carries a negative net)**.

| Style | Where it renders | Extension |
|-------|------------------|-----------|
| Edge | All widths (fixed 4px bar at the viewport bottom) | Hatch layer from notch% to 100%: `repeating-linear-gradient(135deg, color-mix(in srgb, var(--fg) 34%, transparent) 0 3px, transparent 3px 7px)`, above `.edgeTrack`, below `.edgeFill`. Fill stays `var(--user-accent)` and covers the hatch as it advances. Notch: 4px wide (board 3px, rounded to the grid), full bar height, `background: var(--bg-solid)`, above the fill, at notch%. |
| Ruler | `min-width: 640px` digit layout (as today) | Still 25 ticks, each now total / 25. Ticks whose start is at or past the planned end get `.ext`: `repeating-linear-gradient(180deg, color-mix(in srgb, var(--fg) 38%, transparent) 0 3px, transparent 3px 6px)`. Done ext ticks use the same stripes in `var(--user-accent)`. The now tick stays solid accent at full height. Notch: a 7px dot above the ticks, `position: absolute; top: -12px; border-radius: 50%; background: hsl(var(--muted-foreground))`, centred on the notch x (ruler gets `position: relative`). |
| Ink | `min-width: 640px` digit layout (as today) | A 4px vertical line over the digits at the notch x (fraction of the overlay width, same basis as the clip-path), spanning the glyph row with 4% inset top and bottom: `background: var(--bg-solid); box-shadow: 0 0 0 1px color-mix(in srgb, var(--fg) 40%, transparent)`. **No hatch on Ink (spec decision):** hatching glyphs is unreadable; the line is the marker, as on the board. |

Phone shows only Edge (Ruler and Ink only exist in the `min-width: 640px` digit layout today; not
changed).

Fill step-back: when time is added, the fill fraction drops (elapsed / bigger total). See Motion.

## Ended look and sound (4C)

| Element | Contract |
|---------|----------|
| Alarm | The user's chosen sound and volume rings once at the wall-clock end, again at end + 30 s and end + 60 s, then never again for that block. Keyed off `endsAt`, not ticks. If the tab was hidden past a nudge time, missed nudges are not replayed; only nudges still in the future fire. |
| Cancel | Any input cancels remaining nudges: any keydown, any pointerdown in the page, +1, Start, reset. |
| Chrome | On entering ended, `data-chrome-idle` is removed at once and `useChromeIdle` does not re-arm while ended. The footer and hints fade in over today's 0.8s. |
| Breathing | The digits (desktop wrapper including the ink overlay, phone stack, strip line) pulse: `animation: bf-breathe 2.4s ease-in-out infinite`, `@keyframes bf-breathe { 50% { opacity: 0.5 } }`. Stops on leaving ended. |
| Tab title | On entering ended, capture `document.title`, set "Time's up · Be Focus". On leaving ended (any path, including unmount), restore the captured value exactly. |
| Announcement | Polite live region: "Time's up. Focus block done, 25 minutes." / "Time's up. Break done, 5 minutes." |

## Keyboard and focus

### Key map (extends `useTimerKeyboard.ts`)

| Key | Idle / Paused | Running | Ended |
|-----|------|---------|-------|
| Space | Start (today) | Pause (today) | No-op (play is dimmed); still cancels nudges |
| R | Reset (today) | Reset | Reset |
| `+` or `=` | No-op | Add 1 minute | Add 1 minute (resumes the block) |
| `-` | No-op | Remove 1 minute, unless 1:00 or less left | No-op |
| Enter | No-op | No-op | Start break / Start focus / Finish session |
| Escape | - | Closes an open tray | Closes an open tray |

- `+` arrives with Shift on most layouts: the modifier guard must allow Shift for `+` only
  (match on `event.key === '+'`). `=`, `-` and Enter keep the no-modifier rule. Numpad `+` / `-`
  work through the same `event.key` values.
- Same guards as today: repeat, editable targets and guarded containers are ignored. Enter is also
  ignored when the target is a button, link or other activatable element (it activates that
  element natively instead), with one exception: while ended, Enter on a target with
  `aria-disabled="true"` (the dimmed Play, the dimmed −1) goes to the global handler and starts the
  next block **(checker fix)**. A focused live +1 keeps native activation (adds a minute); the
  focus rule below keeps that case rare.
- `aria-keyshortcuts`: −1 `"-"`, +1 `"="`, Pause/Start `"Space"` (today), Reset `"R"` (today),
  primary `"Enter"`.

### Focus order (DOM order)

Desktop: header controls -> ended primary (when present) -> footer: now-playing chip, slot 1,
slot 2, slot 3, slot 4, settings. Phone: ended primary sits before the footer in the DOM even
though the footer is `flex-col-reverse`.

| Moment | Focus rule |
|--------|-----------|
| Block enters ended | If focus is inside the footer (a mouse user who clicked Play still has focus on slot 2), move it to the ended primary so the "Enter start break" hint holds **(checker fix)**. Otherwise focus is not moved (the alarm and live region announce; Enter works globally). |
| Primary activated | The ended group unmounts; focus moves to slot 2 (now Pause, the next block is running). |
| +1 at 00:00 by keyboard on +1 | Focus stays on +1. |
| +1 at 00:00 by keyboard while focus is on the primary | Primary unmounts; focus moves to slot 4 (+1). |
| Tray closed | Focus returns to its trigger if focus was inside the tray. |

### Screen reader announcements

One polite `sr-only` live region next to the existing `role="timer"` span:

| Event | Copy |
|-------|------|
| Add | "Added 1 minute" / "Added 5 minutes" / "Added 10 minutes" |
| Add at 00:00 | "Added 1 minute. Block resumed." (amount varies) |
| Remove | "Removed 1 minute" / "Removed 5 minutes" / "Removed 10 minutes" |
| End | See Ended look and sound |
