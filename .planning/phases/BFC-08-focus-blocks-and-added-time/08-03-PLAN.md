## Phase Goal

**As a** person running focus sessions, **I want to** be told clearly but briefly that my block
is over, by sound, title and screen reader, **so that** I notice the end without the alarm nagging
me forever.

<objective>
Third slice: the ended cues. Move the alarm out of Timer into `useEndedCues`, ring once plus two
nudges keyed off the block's wall-clock end, cancel on any input, set and restore the tab title,
breathe the digits, announce once in a single polite live region, and apply the UI-SPEC focus
moves. TimerButtons only gains data hooks for focus targeting.

Purpose: BLK-01 (the user notices the end and stays in control; the cue never loops).
Output: new hooks/useEndedCues.ts; Timer.tsx, CSS and TimerButtons.tsx edits.
</objective>

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-08-08 | Denial of service (UX) | useEndedCues | mitigate | No `loop`, at most the three NUDGE_OFFSETS_MS rings per block, all timeouts cleared on input and on leaving ended or unmount |
| T-08-09 | Tampering | capture listeners | mitigate | Listeners only clear timeouts; they never call preventDefault or stopPropagation, so other handlers (keyboard shortcuts, dialogs) are unaffected; removed on leaving ended |
| T-08-10 | Information disclosure | tab title | accept | Title text is fixed copy; the captured title is restored verbatim and never logged |
| T-08-11 | Spoofing | alarm url | accept | Urls come from the existing sounds store (same source as today); this plan does not widen where sounds load from |
</threat_model>
