## Phase Goal

**As a** person running focus sessions, **I want to** have the timer stop and wait at 00:00
instead of jumping to the next block, with its length measured on the real clock, **so that** I
decide when a block ends and what it really took.

<objective>
First vertical slice of Phase 8: the block run engine. Replace the tick-counting timer with an
explicit block list and status (idle / running / paused / ended) anchored on a wall-clock `endsAt`.
At 00:00 the store enters `ended` (one transition, owned by the store), the alarm rings once, and
nothing advances by itself. Every transition produces a Zod-valid block record through a single
`onRecords` callback (persisted by 08-06 for guests and 08-08 for accounts).

Purpose: BLK-01 (ended state, alarm, waits) and BLK-05 (lengths from the wall clock). After this
plan a user sees the timer stop at 00:00; moving on uses today's footer Next (the ended footer and
Start break arrive in 08-02 and 08-04).

Seam with Phase 9 (09-07 interfaces): the store exposes `sessionId`, `blocks: Block[]`,
`currentBlockId`, `status`, `endsAt`, `timeLeft` (seconds) and
`seedBlocks({ sessionId, blocks: { id, kind, plannedSeconds }[] })`, as Phase 9 assumed, plus the
08-CONTEXT differences (signed `addedSeconds`, `idle` status, `endsAt`). Further differences, stated
plainly: `currentBlockId` is always a string (the timer always has a block); `index` is the 0-based
list position; a re-run block (R, skip back) keeps its id, because Phase 9 links tasks by block
id, and its record accumulates: actualSeconds adds every earlier run's actual time, startedAt stays
the first run's start, and outcome, endedAt and addedSeconds are those of the last run, so time
actually spent is never lost; skipping forward from ended keeps 'finished' (the block ran to
00:00); skip back from running or paused records the current block as 'skipped' and re-runs the
previous block under the same accumulate rule; a block still running or paused when the tab closes
or reloads is finalised on pagehide as 'reset' with wall-clock actual time (engine `pendingRecord`,
wired by 08-06 for guests and 08-08 for accounts); applySettings goes through resetSession (which
seeds the blocks), never through seedBlocks - same behaviour, noted so Phase 9 is not surprised; blocks that never started produce no record; the default
block list has no break after the last focus block; `sessionId` is replaced when the session is
finished ("Finish session" / skip past the last block), on reset and on Session settings apply, not
on the modal's Continue; seeding while live requires the same `sessionId`; the legacy fields
(`timeLeft`, `isRunning`, `isWorking`, `currentSession`) stay and are derived, and `completed` is new.

Output: packages/types/blocks.ts, lib/blocks/blocks.ts with its check, the store rewritten on it,
the worker sending ticks, Timer wired to ticks and the ended alarm, SessionTitleDisplay aware of
ended.
</objective>

New contract, packages/types/blocks.ts (create exactly these names):

```typescript
import { z } from 'zod'
export const BLOCK_KINDS = ['focus', 'break'] as const
export const BLOCK_OUTCOMES = ['finished', 'skipped', 'reset'] as const
export type BlockKind = (typeof BLOCK_KINDS)[number]
export type BlockOutcome = (typeof BLOCK_OUTCOMES)[number]
export const MAX_BLOCK_INDEX = 199
export const MAX_PLANNED_SECONDS = 21_600
export const MAX_ADDED_SECONDS = 21_600
export const MAX_ACTUAL_SECONDS = 86_400
export const MIN_EPOCH_MS = 1_704_067_200_000 // 2024-01-01
export const MAX_EPOCH_MS = 4_102_444_800_000 // 2100-01-01
export const MAX_BLOCK_RECORDS_PER_REQUEST = 100
export const blockRecordSchema: z.ZodType<BlockRecord> // object + refine(startedAt <= endedAt)
export interface BlockRecord {
  id: string; sessionId: string            // uuid
  kind: BlockKind; index: number           // int 0..MAX_BLOCK_INDEX
  plannedSeconds: number                   // int 1..MAX_PLANNED_SECONDS
  actualSeconds: number                    // int 0..MAX_ACTUAL_SECONDS
  addedSeconds: number                     // int -MAX_ADDED_SECONDS..MAX_ADDED_SECONDS (signed net)
  startedAt: number; endedAt: number       // int epoch ms, MIN_EPOCH_MS..MAX_EPOCH_MS
  outcome: BlockOutcome
}
```
