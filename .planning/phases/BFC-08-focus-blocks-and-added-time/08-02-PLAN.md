## Phase Goal

**As a** person running focus sessions, **I want to** see that my block is done and start the
break (or add a minute) myself at 00:00, from the screen or the keyboard, **so that** the session
moves on when I am ready.

<objective>
Second slice: the ended block UI under the digits and the keyboard paths. Desktop gets the ended
group in `.under` (label, primary, hints; ruler hidden); phone gets the label above the stacked
digits and the primary in its own row; Enter starts the next block, `+` / `=` add a minute
(including at 00:00), `-` removes one. Height rules keep everything clear of the footer.

Purpose: BLK-01 (the ended state the user controls) and the keyboard half of BLK-02 (add time to a
just-ended block). Footer buttons for adjusting come in 08-04, the tray in 08-05.
Output: Timer.tsx ended markup, its CSS, extended useTimerKeyboard.
</objective>

Extend the keydown handler per UI-SPEC "Key map" and CONTEXT Q2:
- Modifier guard: return on metaKey, ctrlKey or altKey; return on shiftKey unless `event.key === '+'`
  (Shift is allowed for `+` only).
- `event.key === '+'` or `'='`: call `store.getState().adjust(1)`; when it returns true,
  preventDefault. Works while running and while ended (the store's canAdjust decides).
- `event.key === '-'`: `store.getState().adjust(-1)`, preventDefault when applied (refused at 1:00
  or less, while paused, idle or ended).
- `event.key === 'Enter'`: only when `store.getState().status === 'ended'`. If the target matches
  ACTIVATABLE_SELECTOR and is not `[aria-disabled='true']`, return (the element activates natively);
  otherwise preventDefault and call `store.getState().startNext()`.
- Keep the existing guards (defaultPrevented, repeat, editable targets, guarded containers) in front
  of all new keys; numpad keys arrive with the same `event.key` values, so no extra handling.
