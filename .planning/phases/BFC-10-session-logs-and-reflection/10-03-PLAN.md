## Phase Goal

**As a** person who works in focus blocks, **I want to** note what got done at each break and see an
honest summary and history of my sessions, **so that** I can see what I actually did and what to
change next time.

<objective>
Ship the signed-in data path for Phase 10: one new route trio `routes/logs/` with four routes,
wired into `app.ts`, plus the later flag on the existing task patch and plan link routes.

Purpose: LOG-02 (logs saved and editable), LOG-04 (history read path; there is no GET for block
records today), LOG-07 (later flag and ticks on closed sessions).
Seams consumed: Block record (`focus_blocks`), Plan and links (`task_block_links`, `putUserTaskLinks`
returns 404 'No open plan' for closed plans, which is why `PUT /user/block-links` exists), Tasks.
Output: logs.route.ts / logs.handler.ts / logs.index.ts, app.ts entry, laterAt stamping, later
clearing on plan.

Discretion decisions recorded here:
- `PUT /user/block-links` is a separate route rather than relaxing `/user/task-links`, so the
  Phase 9 open-plan guarantees stay byte-identical. It accepts only `completed` (no planned /
  worked toggles) and writes the same `completed` / `completedAt` columns plus `tasks.completed`,
  so there is still one completion state, not a second path.
- History window: `days` default 35 (the 5-week calendar), max 62. Sessions are selected by any
  record starting inside the window, then all records of those sessions are returned, so a session
  never splits across pages. Capped at 2000 records per response.
</objective>
