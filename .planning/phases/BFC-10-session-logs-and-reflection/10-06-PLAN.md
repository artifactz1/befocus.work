## Phase Goal

**As a** person who works in focus blocks, **I want to** note what got done at each break and see an
honest summary and history of my sessions, **so that** I can see what I actually did and what to
change next time.

<objective>
The client data layer for logs: guest storage and the account API behind one hook.

Purpose: LOG-02 (save and edit a block log), LOG-06 (guest logs survive a refresh), the history
read for LOG-04.
Seams consumed: Routing (10-03 routes on the typed client), guest storage helpers
(`readStored` / `writeStored` / `defaultStorage`), Phase 8 guest records
(`readGuestRecords`), Phase 9 guest link history (`GUEST_LINK_HISTORY_KEY`,
`parseGuestLinkHistory`, `toGuestLinkHistory`), guest tasks (`GUEST_TASKS_KEY`, `parseGuestTasks`,
`toGuestTasks`), the tasks store (`patchTask`, `setLinks`, `links`, `mode`).
Output: lib/logs/logs-storage.ts + check, hooks/useLogs.ts.

Discretion decisions recorded here:
- Guest keys `befocus.blockLogs` (cap 500, newest kept) and `befocus.sessionNotes` (cap 200),
  envelope `{ version: 1, items: unknown[] }` like `befocus.tasks`.
- The hook works with or without a TasksStoreProvider (the /log page has none):
  `useLogActions(mode, store)` takes the tasks store api or `null` from the caller (callers inside
  the provider pass `useTasksStoreApi()`, the /log page passes `null`), so useToDoStore.tsx is not
  edited. With a store, ticks patch the store (which persists guest tasks itself); without one
  (guest on /log) ticks rewrite `befocus.tasks` and `befocus.taskLinkHistory` directly.
- Guest ticks on the live plan update `links` in the store (`completed`, `completedAt`, `worked`);
  ticks on a closed session update the stored link history entry `${blockId}:${taskId}`.
- A storage write that throws shows the toast "This browser isn't saving your log. Private browsing
  can block storage." once per page load.
</objective>
