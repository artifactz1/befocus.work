## Phase Goal

**As a** person who works in focus blocks, **I want to** note what got done at each break and see an
honest summary and history of my sessions, **so that** I can see what I actually did and what to
change next time.

<objective>
The Log page and its entry point.

Purpose: LOG-04 (browse past sessions by day), LOG-08 (export a past session), LOG-06 (guest history
kept in the browser), LOG-02 (edit a past log), LOG-05 (panel placement).
Seams consumed: middleware `x-befocus-mode` request header and the keyboard guard on
`[data-log-page]` (10-02), `splitSessions`, `sessionDigest`, `groupSessions` (10-05),
`useHistory`, `useLogActions` (10-06), `useSummaryModel`, `SessionSummary`, `ExportMenu` (10-10),
`ImprovePanel` (10-12), `LookPaintScript`, `lookToTokens`, `DEFAULT_LOOK`, `getUserSettings`,
`stripWidths` (lib/plan/strip.ts), `MenuButton`, Tooltip, `isLive` (lib/blocks/blocks.ts).
Output: app/log/page.tsx, LogPage.tsx, HistoryList.tsx, LogButton.tsx, log.module.css; edits to
MenuSettings.tsx and MenuSettingsMobile.tsx.

Discretion decisions recorded here:
- /log has no timer or tasks store (it is outside both layouts), so the page passes `store: null`
  to useHistory and useSummaryModel, and the footer Log button is disabled while a session is live
  (UI-SPEC fallback). The summary's "Open log" acknowledges the session first (10-11).
- The "Timer" back button always pushes `/` (account) or `/guest` (guest); no history sniffing.
- Default selection on desktop is the most recent session; on phone the list shows first.
- "Stopped 10:44" for sessions without a note (stopped before the last block).
- "Show older" loads the next API page when signed in; guests render everything from storage.
- Styles for the page go in a new log.module.css so summary.module.css (10-10) stays the summary's.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser -> Next middleware -> /log | The mode header is set by middleware and read by the server page |
| /log -> API | GET /user/history and log / note saves with the session cookie |
| browser storage -> /log | Guest history is user-editable |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-10-35 | Spoofing / Elevation | x-befocus-mode | mitigate | The header only picks the UI mode and the look; middleware (10-02) overwrites any client value, and every account read or write still goes through the owner-scoped, requireAuth-gated API (10-03), so a forged header shows an error state, never another user's data |
| T-10-36 | Information Disclosure | /log route exposure | mitigate | Only `/log` is added to the open routes (10-02); this plan adds no other route; the account data on /log comes from the API by session cookie |
| T-10-37 | Tampering / XSS | HistoryList, detail | mitigate | Logs, task names and notes from storage or API render as React text; no `dangerouslySetInnerHTML`; guest data enters only through the 10-06 parsers |
| T-10-38 | Tampering | export from /log | mitigate | Same ExportMenu path as the stage: escaped Markdown (T-10-14) and a sanitized file name (T-10-15) |
</threat_model>
