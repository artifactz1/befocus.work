## Phase Goal

**As a** person who works in focus blocks, **I want to** note what got done at each break and see an
honest summary and history of my sessions, **so that** I can see what I actually did and what to
change next time.

<objective>
Mount the live summary in the stage and retire the old completion modal.

Purpose: LOG-03 (end-of-session summary), LOG-07 (live fates on Not done), LOG-02 (logs edited in
the summary are saved).
Seams consumed: `finished` snapshot and `resetAll` (10-08), `endedLinks` / `setEndedLinks` (10-08),
`useLogActions`, `useHistory` (10-06), `toHistoryLinks`, `defaultFate`, `fateOps`, `makeFormat`
(10-04), `useSummaryModel`, `SessionSummary`, `ExportMenu` (10-10), `useTaskActions` setLater /
archive / restore (10-07, Phase 9), `usePlanActions().assignTask` (Phase 9), `useSessionView`,
`StripView`, `labelOf` (Phase 9 ProgressSlot).
Output: components/logs/Stage.tsx; edits to both pages, SessionTitleDisplay, ProgressSlot; delete
SessionCompleteModal.tsx.

Discretion decisions recorded here:
- The digits swap lives in a new `Stage` component that both pages render in place of `<Timer />`;
  Timer.tsx is not edited (the break hook is a store subscription in 10-09, so UI-SPEC's Timer.tsx
  edits are not needed). The `<Timer />` inside SessionSettingsButton.tsx is a different use and is
  left alone.
- The note row is what marks a session finished (10-04 / 10-05), so the initial note (empty
  nextTime and extraDone, `carried` from the `defaultFate` defaults) is saved as soon as the summary
  mounts, independent of the plan. A reload, a closed tab or a failed plan close can then no longer
  leave a finished session reading "Stopped" on /log or outside the 3-session insights gate.
- `planReady = plan?.sessionId === sessionId`. Until it is true, the store's links are the closing
  session's plan, which the Phase 9 closePlan is deleting. Unplanning against them would flip that
  session's history links to planned:false, or 404 and retry into a stale plan.
- Task fate ops apply immediately, as task-only patches while `!planReady`:
  - set-later: `setLater(taskId, true, { keepLinks: !planReady })`
  - clear-later and restore: task-only already
  - archive: `archive(taskId, { keepLinks: !planReady })`
  - unplan: removes the task from `pendingPlan`, and calls `assignTask(taskId, null)` only when
    `planReady`. The new plan starts with no links, so before then there is nothing to unplan.
- Only 'plan-next' waits for `planReady`. If it is still pending at Start new session or Open log,
  a toast says the task was not planned.
- "Next session" plans the task into the first focus block of the new plan (`blocks.find(b =>
  b.kind === 'focus')`).
- No reload guard. The timer run is not persisted (a reload starts a fresh idle run with
  `completed: false`, see useTimerStore.tsx), so `completed && !finished` cannot happen. The note
  saved on summary mount is what marks the session finished. Guessing the ended session from
  history was dropped, because it could mark an earlier stopped session as finished.
- When finished, the header slot always renders the strip view (whatever the Session progress
  pick), every block done, with the finished label.
</objective>
