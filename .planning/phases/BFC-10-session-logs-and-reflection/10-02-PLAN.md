## Phase Goal

**As a** person who works in focus blocks, **I want to** note what got done at each break and see an
honest summary and history of my sessions, **so that** I can see what I actually did and what to
change next time.

<objective>
Ship the three small cross-cutting seams the rest of the phase relies on: the "Ask what got done at
each break" preference (Q8), `/log` reachable by guests and signed-in users (Q3, Q9), and the
keyboard guard for the three new surfaces.

Purpose: LOG-01 (the break prompt can be turned off but is on by default), LOG-04 (history is
reachable for both modes).
Seams consumed: Preferences (Phase 9 Session progress in Customize > Style), Routing
(`middleware.ts`), timer keyboard guard (Phase 9 `useTimerKeyboard.ts`).
Output: `askAtBreak` look key with checks, BreakLogSection, middleware branch, guard selector.

Discretion decisions recorded here:
- `askAtBreak` is a Look key (default true), so it rides the existing look persistence (server
  `PUT /user/themes/active` validated by the shared `lookSchema`, guest `writeGuestLook`) and the
  SSR look hydration. No settings migration column.
- Inside the Customize panel the switch uses `setPreview` like every other section, saved by the
  panel's Apply, exactly as Session progress does. 10-08 reads the applied value `active.askAtBreak`.
- The middleware sets the request header `x-befocus-mode` (`account` / `guest`) on `/log` only and
  always overwrites any client-sent value. The header picks the UI mode; the API still enforces
  auth on every data call.
</objective>
