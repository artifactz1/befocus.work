## Phase Goal

**As a** person who works in focus blocks, **I want to** note what got done at each break and see an
honest summary and history of my sessions, **so that** I can see what I actually did and what to
change next time.

<objective>
The later flag on the client: storage, mapping, the action and the List tab group.

Purpose: LOG-07 (later tasks are kept and visible), LOG-06 (guest flag persists).
Seams consumed: `makeFormat` (10-04), Tasks (`Task.later?` / `laterAt?` from 10-01, `PUT /user/tasks/:id` accepting
`later` from 10-03), `useTaskActions().update`, `assignTask(id, null)`.
Output: edits to tasks-storage.ts, useTasks.ts, getUserTasks.ts, ListTab.tsx, tasks.module.css.

Discretion decisions recorded here:
- `setLater(id, true, opts?)` patches `{ later: true, laterAt: now ISO }` locally, sends `{ later:
  true }` and unplans via `assignTask(id, null)` (as `archive` does). `setLater(id, false)` patches
  `{ later: false, laterAt: null }` and sends `{ later: false }`.
- `setLater` and `archive` take an optional `opts?: { keepLinks?: boolean }`. With `keepLinks:
  true` they skip `assignTask(id, null)` and only patch the task. 10-11 uses this while the store
  still holds the closing session's plan. Those links are history, and unplanning them would
  rewrite the ended session or race the Phase 9 plan DELETE.
- Open excludes later tasks; the order is Open, Add row, Later, Done, Archived, guest note (UI-SPEC
  section 4). The relative date uses `makeFormat().since` from 10-04 so the List tab, the summary
  and /log share one formatter.
- Clearing the flag when a Later task is planned into a block is done in 10-08 (usePlan.ts
  assignTask) and on the server by 10-03.
</objective>
