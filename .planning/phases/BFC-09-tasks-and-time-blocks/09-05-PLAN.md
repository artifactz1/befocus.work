## Phase Goal

**As a** person about to start a focus session, **I want to** see the session laid out as a column
of blocks with real clock times and shape it (add, remove, lengthen) **so that** I know when each
block ends before I begin.

<objective>
The client half of the Plan tab in its planning state, end to end: guest browser persistence of the
plan, seeding from Session settings, server-rendered plan for signed-in users, a revision-tracked
saver whose ensurePlanSaved guarantees the server copy exists before any link write, and the day
column UI with add, remove and nudge.

Purpose: TSK-03. 09-06 calls ensurePlanSaved before every PUT /user/task-links; because a seeded
plan is never edited by the user, the saver must push the seed itself or the first link write
answers 404 "No open plan".
Seams consumed (09-CONTEXT "Dependencies and Seams"): **Guest storage** (Phase 3, as mapped in
09-04's Seam map) and **Session id** (Phase 8, as mapped in 09-02's Seam map). Task 1 re-checks
both.
Output: plan persistence in the tasks store, usePlan.ts, getUserPlan server fetch, List/Plan tabs,
PlanTab.tsx.
</objective>

hooks/usePlan.ts `usePlanActions()`: `addFocus()`, `removeFocus(id)`, `nudge(id, delta)`,
`ensurePlanSaved(): Promise<void>`, `markPlanUnsaved()`. Saver (one per store, kept in a module Map
keyed by the store api so every hook instance shares it): each edit calls setPlan and schedules
`api.user.plan.$put` debounced 300ms (latest plan wins); a seed or session-id adoption saves
immediately. Saves run one at a time (a save requested while one is in flight waits and then
sends the latest plan), and `markSaved(revision)` keeps `max(savedRevision, revision)`, so an older
response can never lower `savedRevision`. On a 2xx it calls `markSaved(revisionSent)`. `ensurePlanSaved` per the corrected
contract: guest mode resolves immediately; if a debounced save is pending, flush it now and await
it; else if `savedRevision < planRevision` (server copy missing or older than the local one), PUT
now and await it; else resolve. It rejects when the PUT fails so the caller can surface its own
toast. `markPlanUnsaved()` sets `savedRevision = -1` so the next ensurePlanSaved PUTs again (09-06
uses it to retry once when a link write answers 404 "No open plan"). Revisions, not timestamps,
decide "older", so client clock skew cannot skip a save. On save failure:
`toast("Couldn't save your plan. Check your connection and try again.", { action: { label: 'Try
again', onClick: retry } })`, no rollback. removeFocus snapshots the previous blocks and shows
`toast('Block 4 removed', { action: { label: 'Undo', onClick: restore }, duration: 5000 })` with the
removed block's number; restore calls setPlan with the snapshot (a normal debounced save).

seed would overwrite a server plan the page could not read).

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser storage -> app | Guest plan and links read back from localStorage |
| Next server -> API | Server render forwards the user's cookie for GET /user/plan |
| client plan copy -> server plan copy | Link writes assume the server holds the plan the client shows |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-13 | Tampering | parseGuestPlan | mitigate | Plan through taskPlanSchema.safeParse, links per item, links to unknown blocks dropped, cap 512; check script covers garbage |
| T-09-14 | Information disclosure | getUserPlan server helper | mitigate | Forwards only the request cookie, logs status only |
| T-09-36 | Tampering (integrity) | ensurePlanSaved | mitigate | Revision compare (`savedRevision < planRevision`) instead of timestamps, immediate save after seed and session-id adoption, no seed when the server fetch failed, so a stale or missing server copy never receives links and a failed read never overwrites a real plan |
</threat_model>
