## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-09-15 | Elevation | PUT /user/task-links | mitigate | Task ids checked with `and(eq(tasks.userId, user.id), inArray(tasks.id, ids))`, block ids checked against the user's own plan, 404 on any miss before writing |
| T-09-16 | Tampering | link upsert conflict path | mitigate | `setWhere: eq(taskBlockLinks.userId, user.id)` so a conflict on another user's row never updates it; every read filters userId |
| T-09-17 | Repudiation / Tampering | workedAt, completedAt | mitigate | Timestamps set by the server only; the body schema has no timestamp fields |
| T-09-18 | Denial of service | link batch | mitigate | Batch capped at 64 items, uuid and positive int validation |
| T-09-19 | Spoofing | drop handler | mitigate | Only the custom type `application/x-befocus-task` is read, and the id must match a task in the store or the drop is ignored |
| T-09-37 | Tampering | putUserPlan dropped-block unplan | mitigate | The unplan update is filtered by `eq(taskBlockLinks.userId, user.id)` and runs in the same batch as the owner's plan upsert, so it can only release the caller's own links |
</threat_model>
