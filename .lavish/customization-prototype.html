Phases 1 and 3

What you won't see, but will feel

Phase 1 · Foundation repair

Customization sits directly on top of these. Fixing them first avoids rebuilding later.

  • Prod settings never load. getUserSettings.ts reads better-auth.session_token; prod sets __Secure-better-auth.session_token. Every theme would silently reset on refresh in prod.
  • No real Tailwind dependency. apps/next depends on tailwind@^4 (an unrelated package) and gets Tailwind 3 by accident. Pick 3 or 4 deliberately.
  • Lint is broken. Biome 1.9.4 wrapper runs a 2.4.13 macOS binary. Fix the pin or migrate to Biome 2.
  • Two hydration paths race. TimerInitializer re-fetches settings after the server already did.

Phase 3 · Persistence and sync

The Persisted cell in the strip above shows this. Behavior:

ApplyPreview becomes the active theme
Signed inPATCH to API, latest write wins
GuestWritten to localStorage
Next visitServer paints theme on first render, no flash
  • Same theme on every device after sign-in.
  • Hammering Apply sends at most one in-flight save; the last value wins.

Scope and design decisions

Each question queues one answer. Changing your mind replaces the unsent answer. Press Send in the Lavish panel when done.

1 · Which features ship in this milestone?

All checked = the full spec you chose. Uncheck anything to cut it (it moves to v2). Dependencies: uploads and URL backgrounds both need the Background tab.

2 · Which timer design replaces the ring?

Pick the default everyone sees. Then decide whether the others ship as options in Style › Timer progress.

3 · Session grid and focus fade

Compare in the Session grid section. Press play on the dashboard and keep the mouse still to see the fade.

4 · Timer controls

Compare in the Timer controls section. The dashboard starts on Keys under timer + pill.

5 · Menu buttons (to-do, sounds, settings, account, customize)

Not restyled in the current plan: Phase 2 only adds the palette button to today's menu. Flip Menu buttons in the toolbar above the dashboard to compare.

6 · Where does Customize open from on desktop?

Try both with the Entry point toggle above the prototype. Mobile uses a bottom-left button and bottom sheet either way.

7 · How do changes commit?

The prototype uses preview + Apply. Closing the panel without Apply reverts.

8 · You tweak a curated preset (e.g. Quiet) and press Apply. Then what?

Curated presets are locked. Try it: load Quiet, change the accent, Apply, and watch the Active theme cell.

9 · Upload limits

Spec defaults shown. These bound R2 cost. The quota is a file count, enforced by the API as well as the UI.

10 · Anything else?

Presets you want, controls that feel pointless, visuals that look off. You can also annotate the prototype directly.
